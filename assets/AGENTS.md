# 이미지 작업 규칙

모든 신규 개체와 교체 이미지의 **외곽·투명 배경 가장자리는 깔끔해야 한다.** 등급과 관계없이 흰색·검정색 매트 테두리, 불투명 배경 잔여물, 거친 오려내기 자국, 들쭉날쭉한 알파, 떨어져 있는 잡픽셀을 남기지 않는다. 일반·희귀의 카툰 윤곽선과 특급·신화의 섬세한 색 윤곽은 각 그림체를 유지하되, 과도한 번짐·안개·입자·광륜으로 실루엣을 흐리지 않는다. 촉수·지느러미·껍질의 실제 형태는 보존하고 발광은 개체 가까이 절제한다. 썸네일과 스프라이트 모든 프레임을 밝은색·어두운색·게임 배경 위에서 원본 크기와 실제 표시 크기로 확인한다. 자세한 판정 기준은 [외곽선·알파 가장자리 공통 기준](references/collectible-style/README.md#외곽선알파-가장자리-공통-기준)을 따른다.

신화 어종 생성·교체 전에는 [신화 스프라이트 제작 절차](references/mythic-sprites/README.md)와 [검수한 개체별 참고](references/mythic-sprites/index.md)를 먼저 확인합니다. 참고 시트의 원본 여백·동작·동일성 검수를 따르고, 셀 경계에서 잘린 원본을 후처리 축소만으로 통과시키지 않습니다.

새 개체의 판매가는 [판매가 책정 기준](../docs/systems/collectibles.md#판매가-책정-기준)을 따릅니다. 등급별 평균은 현재 카탈로그에서 같은 종류·공통/토착 조건으로 계산하며, 과거 이미지 manifest의 가격이나 일부 신규 종만으로 전체 도감 평균을 정하지 않습니다.

새 개체를 기획하거나 이미지를 생성하기 **전에** 위 판매가 기준과 [이동 유형 결정·검증](../docs/systems/collectibles.md#이동-유형-결정검증)을 읽습니다. 같은 등급에서 쓰레기는 물고기보다 크게 낮은 가격대, 장식물은 쓰레기보다는 높고 물고기보다 조금 낮은 가격대를 우선합니다. 현재 종류별 가격 범위를 확인한 뒤 정하며, 외형이 화려하다는 이유로 쓰레기·장식물에 물고기 가격을 그대로 넣지 않습니다.

모든 신규 개체에 `movement_type`, `swim_y_min`, `swim_y_max`, `travel_direction`, `flip_with_direction`을 의도에 맞게 명시합니다. `swim` 기본값이나 기존 개체 복사에 맡기지 않습니다. 게·소라게·왕게·달팽이처럼 바닥을 걷는 설정은 `crawl`을 우선 검토하고, 해파리형 맥동은 `pulse`, 제자리에 붙는 생물·장식물은 `fixed` 여부를 확인합니다. 물속 생물이라는 이유만으로 전부 `swim`으로 등록하지 않습니다. 결정한 이동 방식과 높이 범위는 이미지 동작 설계에도 반영하며, 등록 후 도감뿐 아니라 실제 어항의 기본 위치·이동을 확인합니다.

2026-10-21부터 신규 개체를 출시할 때 `src/features/regions/species-releases.json`에 종 ID와 실제 출시 시각(시간대 포함)을 등록합니다. 메인 신규 어종 탭은 해역에 관계없이 최초 출시부터 7일 동안 표시합니다. 기존 종의 가격·이미지·설명 변경과 누락 보완은 신규 출시로 등록하지 않으며, 과거 종의 출시 시각을 갱신해 다시 노출하지 않습니다.

신화 **어종**은 반드시 4×2의 8프레임으로 제작합니다. 앞 4장은 기본 이동·유영, 뒤 4장은 개체 설정에 맞는 추가 행동이며 6초 주기로 재생합니다. 생성만 하고 끝내지 말고 `mythic-swim.ts`의 시트 선택·프레임·위치 보정에 연결해 어항과 도감 미리보기 양쪽에 반영합니다. 모션 감소에서는 0프레임을 유지하고, 프레임별 배율·전체 불투명도 변화로 동작을 대신하지 않습니다. 추가·교체 후 `npx.cmd vitest run tests/mythic-swim.test.ts`로 전체 카탈로그의 누락을 확인합니다. 일반·희귀·특급 어종의 기본 시트는 2×2의 4프레임이며, 신화 장식물에 8프레임을 일괄 강제하는 규칙은 아닙니다.

스프라이트는 개체의 구조·이동 방식과 물살에 반응할 요소를 먼저 고려해 설계합니다. 움직일 부위를 꼬리·지느러미로 한정하지 않습니다. 흐르는 촉수·몸 가장자리·장식·천·추진기 등 개체에 맞는 요소를 선택하고, 움직이지 않아야 자연스러운 부위는 안정적으로 유지합니다. 한쪽 앞지느러미만 팔처럼 크게 젓는 동작을 피합니다. 네 프레임을 눈 상태만으로 구성하지 않습니다. 머리·몸통 기준점과 크기를 고정하고 제자리 재생에서 위아래 떨림이 없는지 확인합니다. 특급·신화일수록 유영 동작과 반복 연결을 더 세심하게 검수하며, 눈깜빡임은 부가 표현으로 추가합니다. 세부 기준은 [생성·검수 기준](references/collectible-style/README.md)을 따릅니다.

개체(어종·쓰레기·장식물·지도) 이미지를 생성하거나 수정하기 전에 `assets/references/collectible-style/README.md`와 `assets/storage-upload/README.md`를 읽습니다. 등급에 맞는 실제 참고 PNG를 열어 확인하고 이미지 생성 도구의 스타일 참고로 전달합니다. 사용자가 매번 다시 첨부할 필요가 없도록 저장된 참고 이미지를 사용합니다.

- 일반(common)·희귀(rare): `assets/references/collectible-style/common-rare-pongi.png`의 퐁이 카툰풍.
- 특급(epic)·신화(mythic): `assets/references/collectible-style/epic-mythic-starlight.png`의 부드러운 판타지 일러스트풍. 퐁이 그림체에 보석만 더하는 방식으로 대체하지 않습니다.
- 참고 그림은 스타일 기준입니다. 같은 동물·색·무늬를 모든 개체에 복제하지 않습니다. 스크린샷 배경·체커보드·화면 UI를 결과에 넣지 않습니다.
- 특급·신화 참고의 가오리 실루엣(위로 크게 솟은 날개 지느러미·작은 몸통·리본 꼬리)을 새 개체에 그대로 재사용하지 않습니다. 색이나 장식만 바꾼 변형도 금지합니다. 사용자가 그 형태를 명시적으로 요청한 경우에만 사용합니다. 참고에서는 채색·빛·재질만 가져오고, 개체별 몸통·머리·부속지·꼬리의 구조를 먼저 설계합니다.
- 기존 [초기 생성 기록](storage-upload/collectibles/generation-history.md)와 개별 manifest는 과거 생성 기록입니다. 그림체가 충돌하면 위 최신 등급별 기준을 우선합니다. 기존 에셋은 사용자 요청 없이 일괄 재생성하지 않습니다.
- 새 PNG는 `assets/storage-upload/new/YYYYMMDD-HHmmss/` 아래 Storage 경로 계층으로 저장하며 README·manifest에 참고 이미지와 최종 프롬프트를 기록합니다.
- 새 어종은 썸네일과 스프라이트의 모든 프레임에서 머리가 화면 오른쪽을 향하고 앞으로 유영하는 원본으로 만듭니다. 생성 후 실제 이미지를 확인하며, 왼쪽·정면 원본은 새 어종의 최종본으로 채택하지 않습니다. 사용자 지정 예외가 있으면 그 지시를 따릅니다. [방향 규칙과 기존 왼쪽 어종 목록](references/collectible-style/artwork-facing.md)을 반드시 확인하고, 기존 어종은 검토된 방향 값을 보존합니다.

스프라이트 생성·교체 전 [크기·선명도 기준](references/collectible-style/sprite-sizing.md)을 읽고, 셀 해상도와 실제 그림 점유율·몸통 기준점·게임 표시 크기를 검수합니다. 파일 해상도만으로 품질을 판정하지 않습니다.

머리 기준 패치를 실제 이미지 위에서 확인하고 충분한 불투명 표본·매칭 오차를 검사합니다. 투명 패치의 거대한 유한 오차나 기본 `[0,0]`을 성공으로 등록하지 않습니다. [세로 끊김 방지 절차](references/collectible-style/README.md#프레임이-위아래로-끊기는-문제-방지)에 따라 행 전환과 반복 경계를 어항·도감에서 검수합니다.
