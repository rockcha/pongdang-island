# 스프라이트 크기와 선명도 기준

## 크기의 세 가지 기준

PNG 해상도, 프레임에서 그림이 차지하는 비율, 게임 표시 크기는 서로 다릅니다. PNG가 커도 투명 여백이 많으면 개체는 작게 보입니다. 파일 용량만으로 선명도를 판단하지 않습니다.

- 시트 해상도: 2×2 네 프레임을 담는 전체 PNG 크기입니다. 가로·세로는 각각 2로 나눌 수 있어야 합니다.
- 프레임 해상도: 전체 가로·세로의 절반입니다. 예를 들어 1254×1254 시트는 한 칸이 627×627입니다. 1254라는 숫자 자체를 생성 규격으로 강제하지 않습니다.
- 실제 그림 크기: 투명 여백을 제외한 실루엣의 바운딩 박스입니다. 프레임별로 측정합니다.
- 표시 크기: DB의 `size`, 화면 너비 제한, 개체별 `scale`, 프레임 보정 배율에 따라 결정됩니다. `size`는 개체의 코끝부터 꼬리끝까지의 길이가 아니라 투명 여백을 포함한 프레임의 기본 표시 크기입니다.

현재 기본 표시 크기는 `min(species.size, 수조 너비 × 0.4)`이며 변환 배율과 회전 시 유리 경계 보정이 추가될 수 있습니다. 스프라이트 렌더러는 이 크기에 `swimFrameLayout` 보정을 적용합니다.

보정이 없을 때의 대략적인 보이는 폭:

`기본 표시 크기 × 실제 그림 폭 / 프레임 폭`

## 앞으로 생성·교체할 때

[스프라이트 공통 제작 순서](README.md#스프라이트-공통-제작-순서)를 먼저 따른다. 아래는 그 절차에서 크기·여백을 판정하는 기준이다. 신규 시트는 최종 PNG에 정렬을 반영하며, 공통 패딩으로 점유율이 달라지면 실제 표시 크기를 다시 검수한다. 패딩을 추가했다는 이유만으로 `size`를 기계적으로 키우거나 프레임별 배율을 다르게 하지 않는다.

1. 썸네일과 스프라이트는 같은 개체·몸 비율·색을 유지합니다. 썸네일이 선명하다는 이유로 네 프레임도 선명하다고 가정하지 않습니다.
2. 네 프레임 전체의 동작 범위를 먼저 정합니다. 가장 넓은 자세의 긴 축이 셀의 **80~88%**를 차지하는 것을 목표로 하고, **90%를 넘거나 셀 경계를 침범하지 않는지** 검사합니다. 형태상 예외는 배치 README에 이유를 기록합니다. 가늘고 긴 개체를 정사각형으로 찌그러뜨리거나 짧은 축까지 채우지 않습니다.
3. 긴 몸통은 꼬리를 과도하게 말아 높이만 늘리지 않고 작은 화면에서도 길고 읽기 쉬운 실루엣으로 만듭니다. 입·눈·주요 무늬는 실제 표시 크기에서도 구분되어야 합니다.
4. 네 칸의 머리·눈·몸통 기준점과 몸통 크기를 고정합니다. 꼬리·촉수의 동작 때문에 바운딩 박스는 달라질 수 있습니다. **각 프레임을 따로 자르거나 자동으로 꽉 채워 확대하면 안 됩니다.** 필요한 여백 조정은 네 프레임 전체에 동일한 기준과 배율로 적용합니다.
5. 전체 시트를 동일한 비율로 구성하고 셀 사이와 바깥 경계에 실제 알파 투명 여백을 남깁니다. 체크무늬를 배경 픽셀로 그리지 않습니다. 알파 임계값을 바꿔 옅은 발광·촉수도 함께 확인합니다.
6. 원본 100% 배율과 게임 표시 크기, 모바일 DPR 1·2·3에서 확인합니다. 작은 표시에서는 지나친 미세 무늬를 줄이고 눈·얼굴·실루엣의 대비를 우선합니다. 정지 프레임과 반복 재생 모두 검사합니다.
7. 부족한 원본을 크게 보간하는 것으로 디테일이 복구되지는 않습니다. 원본이 흐리거나 테두리가 번져 있으면 이미지 재작업 대상입니다. 그림은 선명한데 너무 작게 보이면 여백·표시 크기를 먼저 확인합니다.
8. 새 어종은 [방향 규칙](artwork-facing.md)에 따라 오른쪽을 향합니다. 교체 대상이 기존 왼쪽 원본이면 원본 방향을 유지하거나 방향 설정까지 함께 변경하고 검증합니다.

80~88%는 새 에셋의 검수 목표이며 기존 에셋 전체를 자동 확대하는 지시가 아닙니다. 몸통 크기를 프레임별로 강제로 같게 만드는 기준으로 사용하지 않습니다.

## 원인 구분

수조 렌더러는 CSS 픽셀 기준 이동·표시 크기와 그리기 버퍼 크기를 분리합니다. 기기 DPR을 반영하되 최대 2배 및 약 400만 버퍼 픽셀로 제한합니다(1배보다 축소하지 않음). Phaser 4 카메라 확대와 역좌표 변환으로 개체 크기·터치·드래그 좌표를 유지하며 창 크기·DPR 변경 시 버퍼와 카메라를 갱신합니다. 설정은 `src/features/aquarium/tank-resolution.ts`, 연결은 `phaser-tank.ts`, 변경 감지는 `tank-inhabitants.tsx`입니다. 원본 품질이나 지나치게 작은 표시 크기까지 복구하는 기능은 아닙니다.

| 확인 결과 | 우선 확인할 원인 |
| --- | --- |
| 원본 PNG를 100%로 열어도 흐림·번짐·계단이 심함 | 원본 생성·리사이즈·알파 테두리 문제 |
| 원본은 또렷한데 게임에서 너무 작음 | 투명 여백 비율과 `size` |
| 원본은 또렷한데 게임에서 뿌옇게 보임 | 실제 텍스처 경로, 렌더러 해상도·기기 DPR, CSS 캔버스 확대, 텍스처 필터, 축소 시 세부 무늬 손실 |
| 프레임이 바뀔 때 크기·위치가 튐 | 몸통 기준점, 프레임 배율, `swimFrameLayout` 보정 |
| 도감은 선명하고 수조만 다름 | 썸네일과 스프라이트가 별개 파일인지, 시트 셀의 실제 그림 크기 |

로컬 파일 검사만으로 현재 Storage에 올라간 바이트나 기기별 표시 품질까지 확인했다고 보고하지 않습니다. 필요하면 공개 URL의 파일과 로컬 파일 해시를 비교하고 해당 기기에서 실제 캔버스를 검사합니다.

## 측정 도구와 검수 기록

저장소 루트에서 실행합니다. PNG를 수정하지 않는 읽기 전용 검사입니다. Windows PowerShell과 System.Drawing을 사용합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/inspect-sprites.ps1 -Output docs/history/sprite-audit.json
```

보고서는 프레임별 알파 32 이상 픽셀의 바운딩 박스·폭과 높이 점유율·픽셀 수를 기록합니다. 흐림 점수나 품질 합격 점수는 아닙니다. 알파 32 미만의 은은한 발광은 측정에서 제외됩니다. 현재 배포 중인 파일 목록이 아닌 과거 배치를 포함한 로컬 시트 목록입니다.

2026-10-15 로컬 68개 시트 점검 결과는 [검수 기록](../../../docs/history/sprite-quality-audit.md)에 있습니다.
