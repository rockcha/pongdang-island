# 신화 개체 스프라이트 제작 참고

신규 신화 어종을 생성하거나 기존 시트를 교체할 때 먼저 읽는다. [검수한 개체별 참고](index.md)에서 비슷한 이동 구조의 시트를 실제로 열고, 연결된 manifest의 프롬프트와 원본 등록 검사를 확인한다. 여기의 시트는 동작·여백 참고이며 새 개체를 기존 생물의 색만 바꾼 변형으로 만들라는 뜻이 아니다. 그림체는 [등급별 기준](../collectible-style/README.md)을 따른다.

## 참고 입력의 역할

생성 전에 개체의 머리·몸통·부속지 구조, 오른쪽 방향, 움직일 부분과 고정할 기준점을 먼저 정한다. 스타일 PNG는 채색·빛·재질 참고이고, 해당 개체의 썸네일은 동일성 참고이며, 배치 가이드는 셀 크기·위치·여백 참고다. 프롬프트에 각 입력의 역할을 명시한다.

스타일 참고의 가오리 형태가 결과에 섞이면 채택하지 않는다. 군체는 작은 물고기들의 집합, 허성은 다섯 팔의 별 형태, 요르문간드는 긴 뱀 형태처럼 개체의 해부 구조가 우선이다. 가이드의 여백은 지켰지만 종의 형태가 바뀐 결과도 실패다. 반복 수정에서 스타일 참고가 형태를 덮어쓰면, 스타일을 반영한 동일성 확정본을 먼저 확보하고 이후에는 그 확정본과 배치 가이드만으로 형태·배치를 보존하는 수정을 한다. 원래의 등급별 스타일 출처와 수정 단계별 입력은 manifest에 남긴다.

## 8프레임 동작 설계

4열×2행의 같은 크기 정사각형 셀에 8개 자세를 행 순서로 배치한다. 앞 4장은 연속 유영, 뒤 4장은 준비 → 전개 → 복귀 → 안정이다. 마지막 안정 자세는 기본 유영으로 자연스럽게 이어져야 한다. 개체에 맞는 물리적 움직임을 먼저 설계하고 눈깜빡임·빛만 바뀌는 시트로 대체하지 않는다.

무리형은 작은 구성원의 흐름과 재결합, 뼈·조각이 있는 개체는 몸통 주위의 제한된 궤도, 길고 유연한 개체는 몸을 따라 전해지는 파동, 고정된 등딱지·섬·껍질은 주변 연조직의 반응을 참고할 수 있다. 머리·몸통·단단한 구조의 크기와 기준점은 고정하고, 양쪽 지느러미를 팔처럼 번갈아 크게 젓지 않는다. 동일한 그림을 반복 복사하거나 프레임별 확대·불투명도로 움직임을 흉내내지 않는다.

## 여백을 먼저 확보

한 칸을 꽉 채우도록 생성하면 코·꼬리·발광이 옆 칸으로 넘어간다. 이미 잘린 프레임을 나중에 축소해도 잃어버린 코·꼬리는 복원되지 않는다. **후처리 전 원본**에서 각 셀의 모든 방향을 검사해야 한다.

처음에는 개체를 셀 중앙 약 60% 영역에 놓고 넉넉한 투명 여백을 가진 배치 가이드를 준비한다. 가이드는 위치를 지정하는 자료이고 최종 동작 생성의 대체물이 아니다. 전체 동작을 포함한 코끝·꼬리끝·촉수·섬·궤도 조각까지 셀 안에 들어가야 한다. 가장 큰 자세를 기준으로 모든 프레임에 같은 배율을 적용한다. 각 프레임의 실루엣을 따로 잘라 확대하거나 중앙 정렬하지 않는다.

[크기 기준](../collectible-style/sprite-sizing.md)의 점유율 목표를 따르되, 큰 동작 때문에 원본에 더 넓은 여백을 둔 경우 배치 README에 이유를 남기고 개체 전체의 표시 배율을 조정한다. 해상도 숫자를 키우는 것만으로 잘림이나 흐린 원본이 해결되지는 않는다.

## 등록을 중단해야 하는 경우

- 원본 셀의 경계에 알파가 있는 코·꼬리·지느러미가 닿거나 다른 자세의 조각이 들어온다.
- 오른쪽 방향이 섞이거나 자세마다 머리·몸통 크기, 해부 구조가 바뀐다.
- 투명 배경 대신 안개·판넬·체커무늬가 그려져 있거나, 발광이 칸 사이를 연결한다.
- 실제 반복 재생에서 몸통이 튀거나 추가 행동 이후 기본 유영으로 갑자기 점프한다.

현재 참고 배치의 원본 검사는 알파 32 이상 실루엣 기준으로 모든 셀에 셀 너비 8% 이상의 여백을 요구한다. 옅은 발광·가는 촉수는 이 수치만으로 판정하지 않고 낮은 알파와 실제 이미지도 함께 본다. 여백 검사 통과는 종의 형태·화질·움직임 검수의 대체물이 아니다.

## 앱 연결과 검증 순서

1. 생성 원본과 최종 시트, 참고 입력 역할·동작 설계·최종 프롬프트를 배치 manifest에 보존한다. 개체별 참고 목록의 이전 6프레임·실패 시안을 최종본으로 재사용하지 않는다.
2. 원본의 셀 경계를 검사하고, 같은 배율을 적용한 최종 시트에서 머리·몸통 패치로 위치를 보정한다. 배치별 registration에 결과를 남긴다. 참고 배치의 준비 스크립트는 해당 배치와 런타임 파일에 종속돼 있으므로 신규 배치에 그대로 실행해 기존 등록을 덮어쓰지 않는다.
3. `mythic-swim.ts`의 에셋 선택·8프레임 선택·위치 보정에 연결한다. 어항과 도감이 같은 시트·보정을 쓰고, 6초 반복과 모션 감소 시 0프레임 유지가 동작하는지 확인한다.
4. `npx.cmd vitest run tests/mythic-swim.test.ts`로 전체 신화 누락을 검사한다. 새 배치에 원본 여백 검사를 추가하고, 제자리 8자세·실제 어항·도감에서 기본/추가 동작과 반복 이음새를 직접 확인한다.
5. [업로드 규칙](../../storage-upload/README.md)에 따라 무손실 압축 후 버전이 있는 새 파일명으로 올린다. 전송한 바이트의 공개 다운로드 해시를 검증한다. Storage 업로드 완료와 앱 배포 완료를 구분한다.

## 참고 목록 유지

검수를 마친 배치 manifest만 `sources.json`에 추가한 뒤 저장소 루트에서 `node scripts/build-mythic-reference-index.mjs`를 실행한다. 같은 종이 여러 배치에 있으면 뒤에 적은 배치를 선택한다. 목록의 이름·이미지 경로·프롬프트 출처는 카탈로그와 manifest에서 생성하므로 `index.md`를 직접 수정하지 않는다. 출처 파일을 이동한 뒤에도 링크 검증을 다시 실행한다.
