# 그림하울 외형과 세로 위치 보정

사용자가 지적한 위아래 끊김과 그림체를 함께 교체한다. 이름·종 ID·등급·가격·서식지·출시일은 유지한다. 내장 `image_gen`으로 썸네일과 특급 2×2 유영 시트를 생성했다. 스타일 입력은 등급별 별빛 가오리의 채색·빛·재질에 한정하고, 가오리 해부 구조는 복제하지 않는다. 기존의 무거운 주름·반점 질감을 줄여 매끈한 남청색·은빛 명암, 가늘고 차가운 눈, 읽기 쉬운 송곳니로 재설계했다. 최종 프롬프트와 선택·제외 사유는 [generation-log.json](generation-log.json), 최종 경로는 [manifest.json](manifest.json)에 있다.

## 원인과 검증

기존 기준 패치는 실제 머리가 아닌 투명한 곳이었다. RGB 검사에서 표본 부족으로 매칭하지 못했는데 기본 0 이동과 매우 큰 유한 RMSE가 성공처럼 저장됐다. 실제 머리 패치로 재측정한 기존 시트의 아래 행은 약 110px 위로 어긋나 있었다. 새 시트도 눈·볼의 실제 불투명 패치를 기준으로 등록하고, 아래 행의 116px 차이를 평행 이동으로 보정했다. PNG별 프레임 확대·재중앙정렬은 하지 않는다. 기존 경로의 위치 보정도 함께 고쳐 과거 이미지 참조에서 같은 끊김을 줄인다.

`register-sprite-anchors.ps1`은 불투명 표본 부족, 매칭 실패, 높은 RMSE에서 중단한다. PowerShell 오류도 성공 종료로 흘러가지 않도록 한다. 기존 투명 패치를 다시 넣는 회귀 테스트가 실패 경로를 검증한다. `registration.json`과 `legacy-anchor-results.json`에 실제 머리 좌표·오차를 남긴다. 가장 넓은 자세를 기준으로 시트 전체에 하나의 배율만 적용하며 원본 바이트는 `sources/*.source`에 보존한다.

`verify-ocean-creatures-preview.mjs`에 이 배치를 전달해 실제 어항·도감의 4프레임, 모션 감소, PC·모바일 화면을 확인한다. 4프레임은 캡처 간격을 고정 주기의 배수가 되지 않게 잡아 모든 자세가 보이는지 검사한다. 고정 위치의 프레임별 머리 기준선 비교는 `artifacts/verify-grimhowl-loop.mjs`로 렌더링한다. 일반 제작 기준은 `assets/references/collectible-style/README.md`의 세로 끊김 방지 절차에 반영한다.

## 등록 순서

준비·여백 검사 → 실제 머리 패치 지정·등록 → `register-epic-art-replacement.mjs` → CLI 신규 migration과 해당 ID만 지정한 `db:catalog` → 로컬 검증 순서다. Storage v2 파일을 무손실 압축해 올린 뒤 등록을 다시 실행하고 공개 다운로드 해시를 대조한다. 기존 v1 URL을 덮어쓰지 않는다. 원격 DB와 Storage 적용은 앱 코드 배포와 구분한다.
