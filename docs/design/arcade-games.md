# 오락실 공통 게임 UI

## 목적과 책임

새 게임에서도 대기 화면·전체 화면 전환·이탈 확인·결과 표시를 다시 만들지 않도록 공통 UI를 사용합니다. 공통 컴포넌트는 배치·표시·접근성만 담당합니다. 게임의 진행 상태, 서버 요청, 타이머, 정산, 재접속 정책은 각 게임이 소유합니다. 공통 UI가 보드를 초기화하거나 보상을 계산하면 안 됩니다.

## 화면 구조

```text
게임 상세 페이지
  공통 헤더 / 오락실 배너 / 게임 플레이·랭킹 탭
  GameModal                 대기 중에는 인라인, 시작하면 native dialog
    GamePanel               게임 탭 패널
      게임별 HUD
      GameStage             크기가 변해도 유지하는 보드·캔버스
        GameStartOverlay    포스터·설명·규칙·모드 선택
        게임별 플레이 화면
        GameOverlay         일시정지·라운드 완료·결과
      GameActions           조작 영역, 필요할 때 결과 공개까지 숨김
      게임별 연결 상태 / 오류 복구
```

`game-layout.tsx`는 패널·보드·조작 영역, `game-start-overlay.tsx`는 대기 화면, `game-overlay.tsx`는 진행 중 안내, `game-modal.tsx`는 모달과 이탈 보호의 진입점입니다. `game-controls.tsx`는 공통 탭과 대기 화면의 기존 import 진입점을 유지합니다.

## 변경하면 안 되는 조건

- 대기 화면에서 플레이로 전환하거나 오버레이를 표시할 때 보드를 다시 마운트하지 않습니다. 특히 Phaser 캔버스와 입력 연결은 유지합니다.
- `GameModal`의 `open`은 화면 전환, `active`는 진행 중 이탈 보호 여부입니다. 둘을 같은 값으로 간주하지 않습니다. 종료·정산 실패 시 모달을 닫지 않고 재시도를 허용합니다.
- 일반 모달은 `contained`, 전체 화면이 필요한 게임은 `fullscreen` 배치를 명시합니다. 공통 CSS가 특정 게임의 내부 클래스 존재로 모달 크기를 결정하지 않습니다.
- 대기 화면은 보드 위를 가리고 입력을 막습니다. 모드 선택 버튼은 고정 영역에 두고 설명·규칙만 내부 스크롤을 허용합니다. 연습 가능 여부를 실전 잔액에 연결하지 않습니다.
- 실전 버튼의 가격 표시는 각 게임이 전달합니다. 무료 실전은 무료로 표시하고 바로 시작하며, 유료 실전은 해당 게임의 참가 확인을 거칩니다. 표시용 가격으로 지갑을 차감하지 않습니다.
- 결과 안내는 기존 dialog 안의 오버레이입니다. 별도 모달을 겹쳐 포커스·스크롤·뒤로가기 처리를 중복하지 않습니다.
- 벽돌깨기의 생존 중 피격은 보드를 유지하는 일시 효과로만 표시합니다. 설명 도감은 대기 화면에서 열고, 모션 테스트와 같은 아이템·방해물 설명 데이터를 사용합니다.
- 결과 공개 전 정답·보상 변화·후속 버튼으로 승패가 드러나면 안 됩니다. `GameActions`의 `revealed`가 false이면 자리를 유지한 채 숨기고 `inert`로 키보드·포인터 입력도 차단합니다. 공개 시점은 각 게임이 결정합니다.
- `onPause`가 있는 물리 게임과 서버 시간제 게임을 구분합니다. 확인창을 열었다고 서버의 마감 시각을 멈추거나 연장하지 않습니다.

## 이탈과 복구

진행 중에는 링크·라우터 이동·브라우저 뒤로가기와 새로고침을 공통 가드로 보호합니다. 취소하면 현재 진행을 유지하고, 확인하면 게임별 정리·정산이 성공한 뒤 이동합니다. 복구 정책은 게임마다 다르므로 실전 진행 보존·연습 초기화·정산 범위를 `exitDescription`으로 전달합니다. 공통 문구에 참가비·라운드 보상 정책을 고정하지 않습니다.

확인 모달은 대기 화면부터 같은 게임 dialog 내부에 portal을 붙입니다. 실전 시작과 동시에 닫히는 확인창의 portal 대상을 바꾸면 종료 애니메이션이 남아 게임 입력을 가릴 수 있으므로 `gameOpen`에 따라 대상을 전환하지 않습니다. 완료 상태의 나가기는 진행 중 확인을 반복하지 않습니다. 아직 공개 중인 결과를 완료로 처리할지는 게임이 결정합니다.

## 배치와 목록

페이지는 화면 높이 안에서 flex/min-height:0으로 구성합니다. 배너 전체 그림과 오락실 경로를 유지하고 중복 제목·목록 버튼을 추가하지 않습니다. 목록은 두 열 카드에 위쪽 썸네일을 배치합니다. 분류 이름과 필터의 원본은 `games.ts`이며 목록은 분류와 보상 방식으로 필터링합니다. 설명이나 가격을 문서에서 별도 목록으로 유지하지 않습니다.

작은 화면은 안전 영역을 확보하고 모달 밖 페이지가 스크롤되지 않게 합니다. 보드 논리 좌표·판정 크기를 화면 비율에 맞춰 바꾸지 않습니다. 가로 화면의 게임별 보드 배치는 해당 게임 CSS에서 처리합니다. 모션 테스트 목록·랭킹·긴 안내만 필요한 영역 안에서 스크롤합니다.

## 수정과 검증

문구·색·아이콘 수정은 해당 화면만 확인합니다. 공통 모달·오버레이·조작 영역을 바꾸면 `npm run test:arcade:ui`로 네 게임의 대기·연습·결과·이탈 흐름을 확인하고 빌드합니다. 결과 공개 전 버튼 비노출, 정산 실패 후 화면 유지, 캔버스 재마운트 방지는 공통 회귀 조건입니다.

`npm run format:arcade`와 `npm run format:arcade:check`로 미니게임 소스의 포맷을 통일합니다. 포맷터는 동결 SQL·DB 스냅샷·생성 엔진 번들을 직접 수정하지 않습니다. 엔진 파일의 포맷을 바꾼 경우 생성 번들의 일치 여부도 확인합니다. 물리·보상·DB 변경은 해당 엔진 테스트와 DB 관리 절차를 추가합니다.

임시 미리보기와 브라우저 프로필은 정식 소스가 아닙니다. 검증을 반복할 스크립트만 `scripts/`로 관리하고, 일회성 산출물은 Git·포맷·앱 검색 대상에서 제외합니다. 브라우저 프로필은 운영체제 임시 경로에 생성합니다. migration·테스트·이미지 manifest·호환용 엔진은 재현 자료로 보존합니다.
