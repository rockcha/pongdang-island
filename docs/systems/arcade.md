# 섬 오락실

게임을 만들거나 수정할 때 [오락실 공통 게임 UI](../design/arcade-games.md)를 먼저 읽습니다. 공통 아이콘 탭·보드 시작 오버레이·배너 보존·스크롤 제한·썸네일과 분류 태그를 모든 게임에 동일하게 적용합니다.

`/arcade`에서 게임 목록을 보여주고 `/arcade/:gameId`로 이동합니다. 장소 이동은 헤더 빠른 내비게이션의 headerPlaces 항목만 사용합니다. 게임 안에 별도 목록으로 버튼을 두지 않습니다. 하위 게임에서도 오락실 배너를 유지합니다.

현재 [그림자 맞추기](shadow-game.md)와 [카드 짝맞추기](memory-game.md)는 10골드 참가·서버 판정·기록 및 무료 연습모드를 구현했습니다. [퐁이의 홀짝 조개](../design/odd-even-game.md)는 첫 베팅금 10골드, 즉시 수령형 보상과 무료 연습을 구현했습니다. 나머지 게임 2개는 준비 중 예시입니다. 게임별 서버 기능은 각 시스템 문서를 따릅니다.

## 게임 추가

`src/features/arcade/games.ts`의 arcadeGames에 고유 id, title, description, icon, status를 추가합니다. 게임 구현 컴포넌트를 component에 연결하고 status를 ready로 바꾸면 상세 페이지에 렌더링됩니다. 큰 게임은 별도 폴더와 React.lazy로 분리할 수 있습니다. rewardMode는 settlement(정산형) 또는 instant(즉시 지급형)이며 메타데이터만으로 실제 보상 지급을 실행하지 않습니다.

entryFee: 생략은 미정, null 또는 0은 무료, 양수는 골드 참가비입니다. dailyLimit: 생략은 미정, null은 무제한, 양수는 하루 참가 한도입니다. 공통 설정은 안내 메타데이터입니다. 실제 차감·횟수 판정은 각 게임 서버가 검증해야 하며 그림자 맞추기는 서버에서 10골드를 차감합니다.

유료 게임 구현 시 클라이언트 설정으로 돈을 차감하지 않습니다. 서버가 가격·일일 기준 시각·참가 한도·보상·재시도 중복 방지를 검증하는 참가/완료 API를 별도로 설계해야 합니다. 그림자 맞추기의 DB 변경과 적용 상태는 해당 문서를 확인합니다.

배너: public/banners/arcade.png. 생성 프롬프트는 assets/references/arcade-banner-manifest.json에 기록합니다.

## 벽돌깨기 실전 검증

실전 보상은 클라이언트 숫자를 신뢰하지 않습니다. 시작 RPC는 잔액과 무관하게 무료로 참가시키고 난수 seed와 엔진 버전을 고정합니다. 클라이언트는 고정 물리 tick의 좌우·터치 목표 위치·발사·다음 라운드 명령을 기록합니다. 터치 목표는 순간 이동이 아니라 엔진의 속도 제한 안에서 따라갑니다. Edge Function은 Auth 서버에서 사용자를 확인하고 해당 사용자의 run만 읽어 같은 엔진으로 재생합니다. 정산 RPC는 service_role만 실행할 수 있으며 지갑 → run 순서로 잠그고 이미 지급한 보상과의 차액만 지급합니다.

라운드 완료 때 checkpoint를 정산하고, 나가기·게임 종료 때 최종 정산합니다. 버전 2는 점수를 집계하지 않으며 라운드 클리어와 동전·보물 획득만 보상에 더합니다. 생명을 잃어도 누적 보상은 유지하고, 계속하기 전에는 입력과 시뮬레이션을 멈춥니다. 이미 정산한 입력 prefix는 변경할 수 없습니다. 재접속은 마지막 검증 checkpoint부터 재개하며 새로고침 직전 미검증 진행은 되돌아갈 수 있습니다. 연습·모션 테스트는 정산·랭킹 API를 호출하지 않습니다. 모션 테스트에서는 골드를 누적하지 않습니다. 물리 재생은 보상 변조 방어이며 자동 플레이 탐지는 제공하지 않습니다.

엔진 변경 시 서버와 클라이언트를 함께 검토하고 기존 run의 버전 호환성을 결정해야 합니다. 버전 1 공유 번들은 과거 기록 정산용으로 보존하며 새 엔진으로 덮어쓰지 않습니다. 새 클라이언트는 진행 중인 버전 1 run의 저장된 checkpoint를 먼저 최종 정산한 뒤 새 규칙으로 시작합니다. 아직 제출하지 않은 과거 탭의 진행은 새 run에 합치지 않습니다. `npm run arcade:engine`으로 현재 Edge 공유 번들을 재생성하고 `npm run arcade:engine:check`, 재생·Edge·SQL 테스트, `npm run db:verify`를 실행합니다. 번들을 수기로 수정하지 않습니다. DB migration → 두 버전을 지원하는 Edge Function → 클라이언트 순서로 배포하고 관련 권한·테이블·함수·인증 거부 응답을 재조회합니다. 원격 적용 상태는 실제 배포 검증 기록과 구분합니다.
