# 섬 오락실

게임을 만들거나 수정할 때 [오락실 공통 게임 UI](../design/arcade-games.md)를 먼저 읽습니다. 공통 아이콘 탭·보드 시작 오버레이·배너 보존·스크롤 제한·썸네일과 분류 태그를 모든 게임에 동일하게 적용합니다.

`/arcade`에서 게임 목록을 보여주고 `/arcade/:gameId`로 이동합니다. 장소 이동은 헤더 빠른 내비게이션의 headerPlaces 항목만 사용합니다. 게임 안에 별도 목록으로 버튼을 두지 않습니다. 하위 게임에서도 오락실 배너를 유지합니다.

게임 목록·참가 조건·분류·준비 상태는 `games.ts`가 원본입니다. 게임별 진행과 서버 계약은 [그림자 맞추기](shadow-game.md), [카드 짝맞추기](memory-game.md), [홀짝 조개](../design/odd-even-game.md) 및 아래 벽돌깨기 검증 절차를 따릅니다. 문서에서 게임별 가격·구현 목록을 별도로 집계하지 않습니다.

## 게임 추가

`src/features/arcade/games.ts`의 arcadeGames에 고유 id, title, description, icon, status를 추가합니다. 게임 구현 컴포넌트를 component에 연결하고 status를 ready로 바꾸면 상세 페이지에 렌더링됩니다. 큰 게임은 별도 폴더와 React.lazy로 분리할 수 있습니다. rewardMode는 settlement(정산형), instant(즉시 지급형), both(동시 적용)이며 메타데이터만으로 실제 보상 지급을 실행하지 않습니다. 동시 적용 게임은 양쪽 필터와 배지에 모두 표시합니다.

entryFee: 생략은 미정, null 또는 0은 무료, 양수는 골드 참가비입니다. dailyLimit: 생략은 미정, null은 무제한, 양수는 하루 참가 한도입니다. 공통 설정은 안내 메타데이터입니다. 실제 차감·횟수 판정은 각 게임 서버가 검증해야 하며 그림자 맞추기는 서버에서 10골드를 차감합니다.

유료 게임 구현 시 클라이언트 설정으로 돈을 차감하지 않습니다. 서버가 가격·일일 기준 시각·참가 한도·보상·재시도 중복 방지를 검증하는 참가/완료 API를 별도로 설계해야 합니다. 그림자 맞추기의 DB 변경과 적용 상태는 해당 문서를 확인합니다.

배너: public/banners/arcade.png. 생성 프롬프트는 assets/references/arcade-banner-manifest.json에 기록합니다.

## 물결 사다리의 베팅과 복구

차감과 지급은 서버의 단일 트랜잭션에서 확정합니다. 지갑을 잠근 뒤 같은 사용자·operation의 기존 결과를 먼저 반환하며, 같은 operation에 다른 금액·유형·선택을 보내면 거부합니다. 경로와 독립적으로 도착 배당을 섞으므로 출발점마다 동일한 배당 분포를 가집니다. 보드나 클라이언트 계산으로 지급액을 결정하지 않습니다.

클라이언트는 요청 전에 계정별 미확인 베팅을 저장합니다. 응답을 받지 못하면 선택을 잠그고 같은 operation으로 결과만 다시 확인합니다. 결과 공개 전에는 배당·지급액·후속 버튼을 감추며 지갑 새로고침도 공개 뒤에 실행합니다. 연습은 로컬 추첨만 사용합니다. 서버에서 이미 완료된 베팅은 화면 이탈로 취소하지 않습니다. 돈 관련 변경 시 사다리 SQL·경로·UI 복구 테스트와 DB 검증을 함께 실행합니다.

## 퐁이 잡기의 기록과 정산

실전은 서버가 참가비를 원장에 기록하고 등장 시간·구멍·대상을 고정한다. 같은 operation의 시작과 완료 재요청은 추가 차감·기록을 만들지 않는다. 클라이언트는 단조 시계로 게임을 표시하고 터치 대상과 상대 시각만 제출한다. 서버가 노출 구간·중복 입력·최소 입력 간격·종료 시각을 검사해 점수를 다시 계산한다. 이것은 점수 변조 방어이며 자동 플레이를 판별하는 기능은 아니다.

완료 확정·즉시 보상 영수증·지갑 입금·골드 원장은 같은 트랜잭션에서 처리한다. 서버 확정 점수와 같은 골드를 지급하며 완료 재요청은 저장한 지급 결과만 반환한다. 이미 종료됐던 과거 기록은 소급 지급하지 않는다. 즉시 보상과 주간 순위는 함께 적용되며, 연습과 중도 종료에는 즉시 보상을 지급하지 않는다.

실전은 창을 숨기거나 나가기 확인창을 열어도 시간이 흐른다. 새로고침 후에는 남은 시간부터 이어갈 수 있지만 아직 제출하지 않은 터치는 복원하지 않는다. 정상 종료의 제출 실패는 화면에 입력 기록을 유지하고 같은 기록을 다시 제출한다. 연습은 서버 참가·정산 API를 호출하지 않는다.

규칙 변경은 진행 기록에 저장한 제한 시간을 기준으로 검증하여 이전 규칙으로 시작한 기록의 마감을 바꾸지 않는다. 두 가짜는 처음부터 등장할 수 있으며 후반에는 등장 비중과 속도가 증가한다. 맞은 모습·구멍별 이펙트는 점수 판정과 독립적이고 다른 입력을 막지 않는다. 효과음은 짧은 Web Audio 합성음으로 재생하며 공통 효과음 음량·음소거·문서 비활성 상태를 따른다. 소리 재생 실패는 입력이나 점수 처리를 실패시키지 않는다.

황금 퐁이 유물은 시작할 때 본인이 보유·장착한 활성 유물만 확인한다. 증가한 수량은 확률 보정이 아닌 한 판 전체 등장 수이며 생성된 보드를 진행 기록에 저장한다. 해제·교체·재접속·재시도로 진행 중인 보드를 다시 만들지 않는다. 연습도 같은 등장 수 규칙을 사용하되 보상·순위에는 참여하지 않는다. 새 방해물 종류를 포함하는 보드 생성 변경은 해당 종류의 이미지와 클라이언트를 먼저 배포한 다음 적용한다.

주간 순위·우편 보상은 기존 오락실 정산 원장을 공유한다. 실제 게임 종료 시각으로 주를 구분하고 주간 경계의 늦은 제출은 정산 유예가 끝나기 전에 닫는다. 배포 전 관련 기존 함수·선물 제약의 원격 정의를 비교하고, 새 migration만 적용한 뒤 권한·정산 스케줄과 합성 계정 롤백 검증을 확인한다. 전체 과거 이력 repair나 baseline 재실행을 대신하지 않는다. 회귀 검증은 `pongi-whack` 모델·SQL·UI 테스트와 `arcade.test.tsx`, DB 검증·빌드를 실행한다.

## 벽돌깨기 실전 검증 절차

실전 보상은 클라이언트 숫자를 신뢰하지 않습니다. 시작 RPC는 잔액과 무관하게 무료로 참가시키고 난수 seed와 엔진 버전을 고정합니다. 클라이언트는 고정 물리 tick의 좌우·터치 목표 위치·발사·다음 라운드 명령을 기록합니다. 터치 목표는 순간 이동이 아니라 엔진의 속도 제한 안에서 따라갑니다. Edge Function은 Auth 서버에서 사용자를 확인하고 해당 사용자의 run만 읽어 같은 엔진으로 재생합니다. 정산 RPC는 service_role만 실행할 수 있으며 지갑 → run 순서로 잠그고 이미 지급한 보상과의 차액만 지급합니다.

라운드 완료 때 checkpoint를 정산하고, 나가기·게임 종료 때 최종 정산합니다. 버전 2는 점수를 집계하지 않으며 라운드 클리어와 동전·보물 획득만 보상에 더합니다. 생존 중 피격은 생명과 짧은 무적 시간만 바꾸고 공·효과·다른 드롭·탄환의 진행을 유지합니다. 목숨 감소 표시는 입력을 막지 않는 효과이며 확인 버튼을 요구하지 않습니다. 마지막 공을 놓쳤을 때만 공을 교체해 즉시 발사합니다. 목숨이 모두 소진되거나 라운드를 마치면 결과를 표시합니다. 이미 모은 보상은 잃지 않습니다. 이미 정산한 입력 prefix는 변경할 수 없습니다. 재접속은 마지막 검증 checkpoint부터 재개하며 새로고침 직전 미검증 진행은 되돌아갈 수 있습니다. 연습·모션 테스트는 정산·랭킹 API를 호출하지 않습니다. 모션 테스트에서는 골드를 누적하지 않습니다. 물리 재생은 보상 변조 방어이며 자동 플레이 탐지는 제공하지 않습니다.

엔진 변경 시 서버와 클라이언트를 함께 검토하고 기존 run의 버전 호환성을 결정해야 합니다. 버전 1 공유 번들은 과거 기록 정산용으로 보존하며 새 엔진으로 덮어쓰지 않습니다. 새 클라이언트는 진행 중인 버전 1 run의 저장된 checkpoint를 먼저 최종 정산한 뒤 새 규칙으로 시작합니다. 아직 제출하지 않은 과거 탭의 진행은 새 run에 합치지 않습니다. `npm run arcade:engine`으로 현재 Edge 공유 번들을 재생성하고 `npm run arcade:engine:check`, 재생·Edge·SQL 테스트, `npm run db:verify`를 실행합니다. 번들을 수기로 수정하지 않습니다. DB migration → 두 버전을 지원하는 Edge Function → 클라이언트 순서로 배포하고 관련 권한·테이블·함수·인증 거부 응답을 재조회합니다. 원격 적용 상태는 실제 배포 검증 기록과 구분합니다.
