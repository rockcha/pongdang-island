# 연속 출석과 28일 출석지

헤더 벨 왼쪽의 달력 버튼에서 출석합니다. 아직 출석하지 않은 날에는 버튼 오른쪽 위에 갈색 점을 표시합니다. 한국 시간(Asia/Seoul) 자정이 기준이며 서버 날짜로 판정합니다. 브라우저 날짜를 바꿔 보상을 받을 수 없습니다.

- 매일 직접 출석 버튼을 누르면 50골드.
- 출석지의 7·14·21일에 달빛 진주새우(`bait_special`) 1개씩 추가 지급.
- 28일에 별잠의 유혹(`bait_epic`) 1개 추가 지급. 완주한 날은 채워진 출석지를 보여주고, 다음 날 1일차의 새 출석지를 엽니다. 새 출석지에도 같은 보상 규칙을 적용합니다.
- 하루 이상 빠지면 진행 중인 출석지가 1일차부터 다시 시작합니다. 이미 받은 보상과 누적 완주 횟수는 회수하지 않습니다.
- 성공 시 불가사리 도장 효과와 보상 토스트를 보여줍니다. 모션 감소 설정에서는 도장 애니메이션을 생략합니다.

`player_attendance`는 마지막 출석 날짜·연속 일수·누적 완주 횟수, `attendance_claims`는 날짜별 보상 기록을 보관합니다. 사용자/날짜 기본키와 기존 지갑의 행 잠금으로 중복 요청·동시 탭의 중복 지급을 막습니다. 골드·미끼 수량·출석 기록·gold_transactions는 하나의 트랜잭션으로 저장합니다. 미끼는 기존 지갑 inventory에 추가하므로 미끼 창고와 낚시 화면에서 그대로 사용합니다. 테스트 충전의 1회 지급 플래그는 변경하지 않습니다.

`attendance_state()`는 서버 날짜·출석 여부·현재 출석지 진행을 반환합니다. `claim_attendance(p_day)`는 조회했던 서버 날짜로 요청하며 날짜가 바뀌면 재조회를 요구합니다. 이미 지급한 날짜 요청의 재시도는 보상을 다시 주지 않습니다. 본인 데이터 SELECT만 허용하는 RLS를 적용하고 직접 쓰기는 차단합니다.

배포 파일: [20261016151410_attendance_28_day_sheet.sql](../../supabase/migrations/20261016151410_attendance_28_day_sheet.sql). [DB 관리 절차](database-management.md)에 따라 증분 migration만 적용합니다. 이 작업에서 실제 원격 DB에는 적용하지 않았습니다.

검증: `npm test -- tests/attendance-sql.test.ts tests/attendance-ui.test.tsx`. 서버 날짜·중복 지급·매주 보상·완주·새 출석지·결석 초기화·골드 한도와 RLS를 로컬 PostgreSQL에서 확인합니다.

출석지는 한 줄 7칸, 총 4줄로 배치합니다. 기존 누적 연속 일수와 지급 기록은 보존하며 진행 중인 이전 출석지는 최대 28일로 맞춥니다. 변경 전 보상에 대한 소급 지급은 하지 않습니다.
