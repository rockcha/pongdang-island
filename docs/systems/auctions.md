# 경매소

`/merchant-street/auctions`에서 누구나 개체·미끼 묶음을 등록하고 골드로 입찰합니다. 물품 검색, 제목(2~60자), 설명(최대 1,000자), 최저 금액, 기간(1·3·7일)을 지정합니다. 등록은 최대 10건이며 물품은 즉시 보관되어 사용할 수 없습니다.

입찰 즉시 최고 입찰금을 보관합니다. 더 높은 입찰이 들어오면 이전 입찰금 전액을 **선물함의 골드 선물**로 반환하고 알립니다. 지갑에 자동 입금하지 않으며 수령 후 다시 사용할 수 있습니다. 본인이 최고 입찰자일 때 금액을 높이면 차액만 추가로 보관합니다. 판매자 본인의 입찰은 금지하며 친구 여부는 제한하지 않습니다.

마감되면 낙찰자에게 물품, 판매자에게 판매 대금을 선물함으로 보내고 알립니다. 입찰이 없으면 물품을 선물함으로 반환합니다. 첫 입찰 전에는 취소할 수 있으며 취소 물품도 선물함으로 반환합니다. 첫 입찰 후 취소·입찰 철회는 지원하지 않습니다. 물품 개체 ID는 기존 거래소 보관 처리로 유지합니다.

## 구현과 정산

- 화면: `src/features/auctions/auction-page.tsx`. 등록 모달 크기를 고정하고 검색 결과만 스크롤합니다. 목록·내 경매·내 입찰과 제목/물품 검색을 제공합니다.
- API: `auction_state`, `auction_post`, `auction_bid`, `auction_cancel`. 서버 시각을 기준으로 마감을 판단합니다.
- 테이블: `auction_listings`, `auction_bids`. 직접 쓰기는 금지하고 인증된 RPC만 허용합니다.
- 보관·배송: [거래소](exchange.md)의 내부 보관 함수를 재사용하고 [선물함](gifts.md)에서 수령합니다. 입찰·등록 UUID는 재시도 중복 결제를 막습니다.
- 잠금 순서: 현재 사용자 지갑 → 경매 → 보관 선물. 이전 입찰자 지갑은 수정하지 않습니다. 마감 정산은 경매만 잠그고 선물을 배송하므로 다른 사용자 지갑 잠금이 필요 없습니다.
- `app_private.auction_settle_due()`는 만료 경매를 최대 100건씩 잠가 정산합니다. 중복 호출해도 한 번만 배송합니다. 목록 조회에서도 같은 정산을 실행합니다.

## 적용

거래소 기본·판매 전용 마이그레이션 다음에 [경매 SQL](../../supabase/migrations/20261016180116_auction_gift_escrow.sql)을 적용합니다. 이 문서는 원격 적용 완료를 뜻하지 않습니다.

SQL은 `pg_cron`을 사용할 수 있으면 확장을 활성화하고 `pongdang-auction-settlement` 작업을 매분 등록합니다. 배포 시 Supabase Cron 활성화와 아래 조회 결과를 확인해야 합니다. 확장이 없는 로컬 환경에서는 목록 조회 시 정산만 동작합니다.

```sql
select jobname, schedule, active
from cron.job
where jobname = 'pongdang-auction-settlement';
```

검증: `npm.cmd test -- tests/auction-sql.test.ts tests/exchange-sql.test.ts`. 보관, 반환 선물 수령, 차액 입찰, 중복 요청, 잔액 부족 롤백, 마감, 유찰·취소, 권한을 로컬 PostgreSQL 호환 환경에서 검증합니다.
