# 미끼 카탈로그와 확률 계약

가격·판매 여부·등급 확률·설명·그림 경로의 원본은 `supabase/catalog/catalog.json`이다. 값을 문서나 화면에 별도로 복제하지 않는다. 변경은 [DB 관리 절차](database-management.md)에 따라 새 CLI migration으로 생성·검증한다. 과거 SQL을 설치 순서로 안내하지 않는다.

상점은 성공 확률과 **성공했을 때의 등급 확률**을 구분한다. 직접 낚시는 서버의 성공 판정과 게이지 조작 성공을 모두 충족해야 지급한다. 성공률이 보장되어도 조작 실패·취소로 포획하지 못할 수 있다. `price=null`은 판매 불가이며 무료가 아니다. 구매는 서버의 가격·잔액 검사와 operation ID 중복 방지를 따른다.

`success_chance_bp`가 지정된 미끼는 성공률 고정형이다. 직접 낚시의 낚싯대 보너스와 통발의 성공률 보너스를 더하지 않는다. 토착종 보너스는 등급 결정 이후 종을 선택할 때만 적용한다. `fish_only` 미끼는 해당 등급의 물고기만 후보로 삼으며 쓰레기·장식물·다른 등급으로 대체하지 않는다. 기존 미끼의 혼합 후보·발견 전용·장식물 전용 규칙은 유지한다.

지그재그 젤리는 계정별 다음 등급을 서버에 저장한다. 최초 일반부터 시작하며 직접 낚시에서는 미끼가 소모되는 준비 요청이 성공할 때 한 번 교대한다. 성공·실패·취소·만료 모두 순서를 되돌리지 않는다. 같은 operation ID 재요청, 진행 중 예약 반환, 검증 실패는 추가 교대하지 않는다. 통발은 회수 시 각 추첨마다 교대하고 실패한 추첨도 포함한다. 재접속·미끼 교체로 초기화하지 않으며 상점·미끼통·창고는 서버가 반환한 다음 순서를 표시한다. 클라이언트는 교대 상태를 직접 수정할 수 없다.

그림은 투명 PNG를 `public/items/baits/`에 저장하므로 Storage 업로드가 필요 없다. 신규 그림의 생성 도구·최종 프롬프트·파일 경로는 [이미지 manifest](../../assets/references/varied-baits-manifest.json)에 남긴다. 종을 장식물로 재분류할 때는 기존 ID·그림·보유 개체·발견 기록을 보존하고 장식물의 위치·속도 제약을 지킨다.

검증은 `tests/varied-baits-sql.test.ts`의 등급 전체 구간·실패 및 재요청 교대·고정 성공률·구매 중복 방지·후보 종류 검사와 미끼 상세 UI 테스트로 수행한다. 이후 `npm run db:context`, `npm run db:verify`를 실행한다. 원격 적용 여부는 해당 배포에서 다시 확인하며 로컬 재생 성공으로 원격 상태를 단정하지 않는다.
