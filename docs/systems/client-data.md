# 클라이언트 데이터 관리

서버 데이터의 원본은 서버이며, 공유 캐시는 TanStack Query가 관리한다. 기존 Context는 화면에 필요한 값과 효과를 제공하는 인터페이스로 유지한다. 인증 세션은 Supabase Auth가 관리하고 Zustand에는 도감 필터처럼 화면 사이에서 공유할 UI 선호만 넣는다. 잔액·경험치·보유량을 Zustand나 영구 브라우저 저장소에 복제하지 않는다.

계정 데이터 키는 계정 ID를 포함해야 한다. Auth가 세션을 React에 전달하기 전에 이전 계정 요청을 취소하고 캐시를 제거한다. 거래 시작 시 캡처한 계정 범위가 바뀌면 늦게 도착한 응답으로 캐시를 채우지 않는다. 읽기 함수는 Query의 AbortSignal을 Supabase 요청에 전달한다.

조회는 화면의 query observer와 기존 명령형 로더가 같은 키를 사용한다. 같은 시점의 요청은 공유하고, 짧은 화면 재진입은 유효한 캐시를 사용한다. 서버 시각을 포함한 캐시를 명령형 화면에 전달할 때는 경과 시간을 반영해 카운트다운이 다시 시작되지 않게 한다. 메뉴는 상세 카탈로그·지난 기록·지갑 초기화를 호출하지 않는 요약 RPC를 공유한다. 완료·만료 표시는 알려진 기한에서 로컬로 갱신한다. 주기적 조회는 앱 루트의 단일 타이머가 활성 쿼리마다 한 번씩 수행하며 다른 기기 변경을 보완하는 용도로 사용한다.

쓰기 요청은 자동 재시도하지 않는다. 기존 거래의 operation ID 유지 및 결과가 불확실할 때 같은 ID로 확인하는 절차를 보존한다. 전체 상태가 포함된 성공 응답은 캐시에 바로 반영하고 해당 도메인을 재조회하지 않는다. 완전한 상태가 없는 다른 도메인은 변경 이벤트로 무효화한다. 금액이나 경험치를 서버 확인 전에 증가시키지 않는다.

알림 목록과 배지 수는 같은 RPC 스냅샷으로 받는다. 알림 목록의 표시 제한을 전체 읽지 않은 수에 적용하지 않으며, 선물 배지는 알림 읽음 여부와 별도로 수령 대기 선물을 포함한다. 공지 공개 여부와 친구 요청 참가자 권한은 기존 RLS를 그대로 적용한다. Realtime은 기존 계정 범위 구독을 유지하며 캐시와 화면 상태를 함께 갱신한다.

새 기능을 옮길 때는 중복 로컬 상태와 기존 갱신 리스너를 함께 검토한다. 서버 데이터 키에 필터나 페이지가 영향을 주면 키에도 포함한다. 호출 수 검증과 함께 계정 전환, 늦은 응답, 이벤트 유실, 거래 중복 방지를 확인한다. 캐시 단위 테스트의 호출 감소를 실제 운영 전체 요청량 감소율로 표현하지 않는다.
