# 발전기금 운영

발전기금은 자율적인 실제 원화 후원이다. 게임 골드·경험치·아이템 보상과 연결하지 않는다. 은행과 자동 연동하지 않으므로 유저의 신고는 입금 증명이 아니다.

유저가 **후원했어요**로 입금자명·금액·한국시간 입금 일시를 제출하면 확인 대기로 저장한다. 기존 소식 운영자만 실제 계좌 내역과 대조하여 **입금 확인**을 누를 수 있다. 신고 금액과 실제 금액이 다르면 실제 확인 금액을 입력한다. 확인된 금액만 합계와 순위에 포함한다.

발전기금은 내 섬 메뉴의 퐁당섬 소식 바로 아래에 독립 페이지로 둔다. 후원 신고에는 응원 메시지나 공개 여부 선택을 제공하지 않는다. 서버는 새 신고가 확인 후 명단에 공개되도록 저장한다. 이전 정책으로 저장된 비공개 내역은 소급 공개하지 않는다. 입금자명·일시는 본인과 운영자만 조회한다. 운영자 메모는 본인에게도 표시되므로 다른 사람의 개인정보를 적지 않는다. 신고 저장 성공 뒤 감사 완료 화면을 보여주되 운영자의 입금 확인이 끝났다는 표현은 쓰지 않는다. 네트워크 오류에서는 같은 ID로 결과를 다시 확인한다.

화면은 후원하기·후원자 명단·응원의 한마디 탭으로 나눈다. 탭은 스크롤 영역 밖에 두어 어느 내용에서든 바로 이동할 수 있게 한다. 각 탭 내부의 중복 제목을 생략하고 후원하기 탭에 하트를 전하는 퐁이와 짧은 응원 문구를 둔다. 퐁이는 같은 배율의 여덟 프레임을 앞으로 재생하고 역순으로 복귀하며 모션 감소에서는 첫 프레임을 유지한다. 탭 이동은 조회를 새로 발생시키지 않으며 응원 입력 중 다른 탭을 확인해도 초안을 유지한다.

후원 소개는 하트를 전하는 퐁이의 후원 이야기와 노트북을 두드리는 퐁이의 운영·개발 이야기 두 장으로 구성한다. 같은 높이를 유지하며 5초마다 전환하고 작은 페이지 선택·일시정지 버튼을 제공한다. 다른 탭·입력 모달·백그라운드에서는 전환과 스프라이트 재생을 멈춘다. 마우스를 올리거나 키보드로 조작하는 동안에도 내용을 읽을 수 있도록 전환을 멈춘다. 모션 감소에서는 자동 전환 없이 수동으로 이동하며 정지 프레임을 표시한다. 이 슬라이드는 API를 추가 호출하지 않는다.

상단 현황은 금액 대신 운영자가 확인한 신고 건수와 고유 후원자 수를 표시한다. 같은 사람이 여러 번 후원하면 횟수는 각각 세고 인원은 한 번만 센다. 확인 대기·반려는 제외하고 확인 취소는 횟수에서도 빠진다. 후원자 명단은 기존 누적 확인 금액 순서를 유지하되 같은 크기의 아바타·이름으로 통일한다. 상위 열 명은 작은 순위 숫자와 닉네임 아래 개별 직함·이모지를 표시하고, 나머지는 숨은 공신으로 표시한다. 이 직함은 후원자 명단에서만 사용하며 게임의 칭호나 보상을 지급하지 않는다. 큰 칭호 배지·메달은 표시하지 않는다. 금액은 본인·운영자 내역에서 확인한다.

응원의 한마디는 후원 여부와 관계없는 별도 공개 공간이다. 로그인한 유저가 100자 이내로 작성하며 최신 세 건부터 더 불러온다. 아바타·닉네임·날짜와 글을 표시하고 본인은 삭제, 기존 소식 운영자는 숨김 처리할 수 있다. 삭제는 숨김으로 보존하며 삭제 후에도 30초 간격·하루 30건 제한은 유지한다. 같은 ID·같은 본문의 재시도는 중복 작성하지 않는다. 응원 글은 후원 횟수·금액·게임 보상을 바꾸지 않는다.

같은 은행 거래를 두 번 확인하지 않도록 운영자는 계좌 내역을 먼저 대조하고, 가능하면 은행 거래 식별값을 입력한다. 동일 식별값의 중복 확정은 거부한다. 식별값을 생략하면 서로 다른 신고가 같은 실제 입금인지 시스템이 판별할 수 없다. 오확인은 **확인 취소**로 대기로 돌린 뒤 수정하거나 반려한다. 모든 처리에는 운영자·전후 상태·금액 이력을 남긴다.

응답이 끊긴 경우 같은 작업 ID로 다시 확인한다. 금액이나 대상을 바꾸어 재시도하지 않는다. 동시 처리된 오래된 화면의 확인은 거부하고 최신 내역을 불러오게 한다. 일반 계정에는 원본 테이블 접근권을 주지 않고 본인 내역과 동의한 공개 명단만 RPC로 제공한다.

검증은 `tests/development-fund-sql.test.ts`의 권한·재시도·정렬·개인정보 경계와 UI 테스트를 실행한다. 원격에서는 `tests/fixtures/development-fund-smoke.sql`을 합성 계정만 생성하는 트랜잭션 안에서 실행하고 반드시 롤백한다. 배포 경로와 검증 기준은 [DB 관리](database-management.md)를 따른다.
