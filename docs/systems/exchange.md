# 거래소·벼룩시장과 물품 보관

거래소는 묶음 전체를 거래하고, 벼룩시장은 품목별 개당 가격으로 필요한 수량만 거래합니다. 팔아요는 물건을, 사요는 요청 수량 × 개당 가격의 합계를 먼저 맡깁니다. 제목과 물품 이름을 검색하고 종류·내 글로 좁힐 수 있습니다.

## 예치와 정산

화면의 상점 판매가는 조회 시점 카탈로그의 개당 판매가이며 거래 작성자가 정한 가격과 구분합니다. 과거 글·묶음에도 최신 참고 가격을 붙이지만 원래 예치 물품 스냅샷이나 재시도 요청 비교에는 넣지 않습니다. 연료와 가격을 확인할 수 없는 물건에는 임의의 참고 금액을 표시하지 않습니다.

거래 가능한 개체는 보관함에 있고 판매·선물 예약 중이 아닌 인스턴스만 서버에서 선택합니다. 지도·유물·낚싯대·테스트 개체와 미끼는 거래 대상이 아닙니다. 클라이언트의 이름·보유량·합계는 권한이나 재고 판단의 근거가 아닙니다.

사요 등록은 구매대금을 먼저 차감하고, 납품 때 해당 금액만 판매자 지갑으로 즉시 지급하며 예치금과 요청량을 함께 줄입니다. 마감하면 미사용 예치금만 반환합니다. 팔아요 구매는 구매자 차감과 판매자 입금을 같은 트랜잭션에서 처리합니다. 모든 골드 이동은 거래 내역을 남깁니다.

물건 배송과 취소 반환은 기존 거래 선물·우편 수령 방식을 재사용합니다. 수령 전 물건은 다른 용도로 사용할 수 없고, 수령 시 기존 보유 한도 검사를 거칩니다. 부분 거래는 맡긴 개체 UUID를 분할하며 새 개체를 생성하지 않습니다. 전체 수량 거래는 기존 소포를, 일부 거래는 정확한 인스턴스를 새 소포로 나누어 배송합니다.

## 재시도·경합·권한

등록은 본인 지갑, 거래는 양측 지갑을 UUID 순서로 잠근 다음 게시글·물건을 잠급니다. 취소도 지갑 다음 게시글 순서입니다. 같은 글의 수량 차감을 직렬화하며 잔액이나 어느 한 품목이 부족하면 배송·골드·나머지 품목 변경도 전부 롤백합니다.

벼룩시장 쓰기는 사용자 + operation UUID와 원본 요청·결과를 저장합니다. 같은 요청의 재전송은 기존 결과를 반환하며 같은 UUID로 내용을 바꾸면 거절합니다. 통신 결과가 불확실할 때 입력을 고정하고 동일 요청으로 결과를 다시 확인합니다. 계정 전환 후 이전 요청은 새 계정의 캐시나 화면을 갱신하지 않습니다.

공개 RPC는 INVOKER, 내부 진입점은 auth.uid()를 검사하는 DEFINER와 빈 search_path를 사용합니다. 예치·정산 도우미와 비공개 테이블은 인증 사용자도 직접 접근할 수 없습니다. 읽기는 account Query, 쓰기는 accountCommand를 사용하고 지갑·보관함·우편·목록의 관련 캐시를 무효화합니다.

## 미끼 거래 종료와 운영

미끼 차단 migration은 새 등록과 기존 활성 미끼 판매·구매 주문을 종료합니다. 미끼가 포함된 묶음은 다른 품목까지 모두 반환하여 물건이 묶이지 않게 합니다. 금액을 맡긴 주문은 원래 금액의 소포를 반환하고, 유효한 미끼 없는 판매와 종료 기록은 보존합니다. 우편의 중복 수령 방지는 기존 절차를 따릅니다.

DB의 자산 검증과 게시글 트리거에서도 차단하여 이전 클라이언트의 우회를 막습니다. 친구 선물의 미끼 전송 규칙은 별개입니다.

배포는 [DB 관리 절차](database-management.md)에 따라 새 migrations만 적용하고 RPC·권한·반환 결과를 다시 조회합니다. 과거 초기 SQL이나 baseline을 재실행하지 않습니다. DB 적용과 클라이언트 배포는 별도로 확인합니다.

검증은 tests/flea-market-sql.test.ts, tests/disable-bait-market-sql.test.ts, tests/flea-market-ui.test.tsx와 기존 거래소·우편 테스트를 사용합니다. 예치·부분 거래·취소·재시도·잔액/재고 부족 롤백·권한·기존 주문 반환을 검사합니다. PGlite 직렬 요청 검증은 실제 다중 연결 부하 검증을 대신하지 않습니다. 변경 후 db:context, db:verify, client-data:check와 build를 실행합니다.
