# 레벨과 경험치

친구 돕기는 완료한 방문자에게 경험치를 지급한다. 유인은 통발별 도움 기록을, 청소·먹이주기는 한국 시간 기준 방문자·친구·활동별 일일 완료 알림 기록을 원천으로 사용한다. 같은 친구의 여러 어항을 반복 완료해도 일일 지급은 늘지 않는다. 완료 이전 단계·재시도에는 추가 지급하지 않으며, 적용 이전의 도움 기록에는 소급 지급하지 않는다. 기존 경험치 원장과 레벨업 보상 처리를 함께 사용하고 도움 실패 시 경험치도 롤백한다.

레벨은 플레이 기록을 나타낸다. 기존 플레이를 인정하면서도 수동 낚시에 성장의 중심을 두기 위해 도입 시 기록은 횟수로 환산하고, 이후에는 포획 등급과 획득 경로별로 지급한다. 가격·거래량·현재 보유 개체 수에 연동하지 않는다. 선물, 거래, 생산, 테스트용 지도 조각 수 변경으로 경험치를 지급하지 않는다.

경험치는 서버 결과 확정과 같은 트랜잭션에서 기록한다. 직접 낚시는 실패를 포함한 확정 결과, 통발·어선은 수령 시의 실제 개체가 기준이다. 지도 조각은 보관함 개체를 만들지 않아도 낚시 성공 결과로 인정한다. 자동 낚시 실패는 별도 경험치를 주지 않는다. 쓰레기의 절반 보정과 자동 낚시 보정을 적용한 뒤 개체별로 반올림한다. 구체적인 수치는 migration과 SQL 테스트가 기준이다.

도입 migration은 세 원천 테이블의 쓰기를 잠시 잠근 뒤 기존 확정 기록을 환산하고 신규 지급 트리거를 설치한다. 시각 비교에 의존하지 않으므로 진행 중인 낚시·미수령 통발·어선은 이후 확정 시 신규 기준으로 지급한다. 과거 환산 경험치는 지급 근거로 따로 보존한다. 이 migration을 원격에 다시 실행하거나 기존 경험치 표를 초기화하지 않는다.

경험치 원장은 사용자·경로·원천 operation/trip ID로 중복을 막는다. 서로 다른 계정이 같은 operation ID를 사용해도 각각 인정한다. 합계 증가는 원장 삽입 성공 시에만 원자적으로 수행한다. 경험치 원장과 합계는 private이며 클라이언트가 지급량이나 타인의 ID를 지정하는 RPC를 제공하지 않는다. 조회 RPC는 로그인한 본인의 레벨과 진행도만 반환한다.

친구 목록은 별도 일괄 조회로 현재 승인된 친구의 ID와 레벨만 표시한다. 요청 대기·거절·친구 해제 상태나 무관한 계정의 경험치 합계는 공개하지 않는다. 레벨 조회 실패가 방문·친구 관리 기능을 막지 않으며 확인하지 못한 값을 임의로 1레벨로 표시하지 않는다.

아바타가 있는 작성자·판매자·방문자·수령자 등은 공통 아바타의 우측 상단에 휘장을 겹쳐 표시한다. 일괄 조회는 계정마다 요청을 합치고 짧게 캐시하되, 사용자 UUID만으로는 조회를 허용하지 않는다. 본인·요청/승인된 친구·실제로 열람할 수 있는 공개 글과 거래의 작성자·공개 반응자·본인에게 보이는 선물 등 기존 표시 범위로 서버에서 제한한다. 친구 코드 검색은 이미 알고 있는 코드를 함께 전달해 확인하며, 친구 전용 건의는 기존 친구/운영자 조건을 그대로 따른다. 총 경험치와 원본 경험치 값은 공개하지 않고, 기존 표시 대상에게만 현재 레벨과 0~1의 경험치 진행 비율을 반환한다. 계정 변경 뒤 늦게 도착한 조회는 버리고, 조회 실패가 기존 링크·선택·방문 기능을 막지 않게 한다. 글 카드나 선택 항목의 이동 영역과 휘장 버튼은 DOM에서도 분리해 휘장을 눌러도 이동·선택되지 않게 한다. 명예의 전당 순위·납품·통발 도움도 기존 권한 검사를 통과한 응답에 표시된 사람의 값만 추가한다.

휘장의 흰 배경 둘레는 현재 레벨 경험치 비율만큼 채우는 얇은 원형 바로 표시한다. 위쪽에서 시계 방향으로 채우고 레벨업 뒤 새 구간으로 초기화한다. 본인 진행도는 일괄 조회의 캐시보다 최신 본인 경험치 응답을 우선해 즉시 갱신한다. 비율이 없는 오래된 응답은 진행도를 추정하지 않고 휘장만 표시한다. 링은 클릭을 가로채지 않고 모션 감소 설정에서는 전환 효과를 생략한다.

레벨은 누적 경험치에서 계산하고 별도로 저장하지 않는다. 필요 경험치가 선형으로 증가하므로 누적 기준은 이차식이며 경계에서 남는 경험치를 다음 레벨로 넘긴다. 레벨로 낚시 확률·판매가·해역 접근 권한을 바꾸지 않는다.

경험치 곡선을 변경할 때는 기존 레벨과 진행률을 보존한다. 지급 원장과 실제 획득 합계는 수정하지 않고, 표시용 곡선 보정값으로 새 누적 기준에 대응시킨다. 화면의 totalXp는 실제 획득 합계를 유지해 환산분이 새 경험치 획득 이펙트로 표시되지 않게 한다. 정수 단위 환산 오차는 새 경험치통의 1 XP 미만이며 레벨 경계를 넘기지 않는다.

레벨업 보상은 적용 후 새로 달성한 레벨부터 기존 보관함의 시스템 골드 선물로 지급한다. 도달 레벨 2~10은 100골드, 11~20은 200골드처럼 10레벨 구간마다 증가한다. 원장 중복 검사와 사용자별 경험치 행 잠금, 보상 지급 상한 레벨, 수령자·도달 레벨별 고유 인덱스로 재시도·동시 정산의 중복을 막는다. 여러 레벨을 한 번에 넘으면 각 단계의 선물을 모두 만든다. 경험치 갱신·선물·알림은 하나의 트랜잭션에서 처리하며 지갑은 선물을 실제 수령할 때만 증가한다. 기존 도달 레벨은 migration에서 지급 기준선으로 기록하며 소급 보상하지 않는다. 클라이언트에 보정값·보상 기준선·임의 경험치 지급 권한을 노출하지 않는다.

휘장은 1–10부터 91–100까지 열 단계로 구분하고 아바타 우측 상단에서 같은 벡터를 사용한다. 평소에는 휘장만 표시하고 클릭·탭 또는 키보드로 열면 정확한 레벨과 휘장 구간을 작은 말풍선으로 보여준다. 작은 표시에서도 선명하게 유지하며 색뿐 아니라 리본·월계·왕관의 추가로 단계를 구분한다. 100레벨을 넘으면 마지막 휘장을 유지하고 실제 레벨 숫자는 그대로 표시한다. 레벨 조회 중에는 구간을 추정해 휘장을 붙이지 않는다.

화면은 헤더의 레벨 배지, 마이페이지의 진행도와 지급 기준, 낚시·수령 뒤 중앙 경험치 이펙트를 사용한다. 이펙트는 골드와 같은 떠오름·반짝임을 사용하되 색과 XP 단위로 구분하고, 골드와 동시에 떠도 겹치지 않게 배치한다. 레벨업 문구도 같은 위치에서 함께 사라진다. 포털은 클릭을 가로채지 않으며 모션 감소 설정을 따른다. 실제 서버 합계 차이를 표시하며 화면 계산만으로 경험치를 적립하지 않는다. 최초 로딩·계정 전환·포커스 복귀는 과거 경험치를 방금 얻은 것처럼 알리지 않는다. 실패한 갱신은 기존 진행도를 유지하고 재조회할 수 있다.

검증은 경험치 SQL·화면 테스트, `db:context`, `db:verify`, 앱 빌드로 한다. 과거 기록 환산, 레벨 경계, 지도 조각, 등급·종류별 지급량, 수령 재시도, 미수령 상태, 서로 다른 계정의 동일 operation ID, 트랜잭션 롤백과 직접 쓰기 차단을 확인한다. 원격 적용 뒤에는 경험치 합계와 원장 합계를 대조하고 본인 조회·권한을 재확인한다.
