# 농장 저장과 골드 거래

운영 농장은 계정 지갑을 사용한다. 독립 실행하는 편집기 미리보기의 연습 돈·초기화·테스트 재고를 운영 저장으로 가져오지 않는다. 기존 섬 농장과 탑뷰 농장의 저장은 분리하며, 기존 섬 문서를 덮어쓰지 않는다.

화면은 행위만 서버에 전달한다. Edge Function은 로그인한 사용자를 확인하고, 서버 시각·카탈로그·저장된 재고로 공통 규칙을 실행한다. 모든 로그인 계정은 자신의 농장을 이용하며 사용자 ID는 인증 결과에서만 가져온다. 클라이언트가 계산한 잔액, 가격, 완성 시각이나 전체 저장 문서를 정산 근거로 받지 않는다. 서비스 전용 RPC는 공유 지갑을 먼저 잠근 뒤 농장 버전과 기존 골드를 비교하고, 지갑·거래 기록·농장 저장을 같은 트랜잭션으로 변경한다. 브라우저 역할에는 정산 RPC와 비공개 테이블 접근을 허용하지 않는다. 비공개 테이블에 정책이 없는 것은 서비스 전용 경계를 유지하기 위한 의도다.

확정 응답은 계정별 Query 캐시에 게시한다. 다른 계정에서 늦게 돌아온 응답은 반영하지 않는다. 화면의 골드 효과와 공통 지갑 효과가 중복되지 않도록 확인된 지갑을 게시하기 전에 기존 효과 이벤트를 사용한다. 통신 결과가 불확실하면 원래 명령·거래 ID를 유지하고 새 쓰기를 잠근다. 자동으로 재전송하지 않으며, 사용자가 결과 확인을 눌렀을 때 같은 요청을 확인한다. 확정된 버전 충돌은 최신 상태를 조회하고 사용자에게 재시도를 맡긴다.

되돌리기는 서버에 남은 직전 배치 상태만 복원하며 현재 골드는 유지한다. 구매·판매·생산으로 버전이 바뀌면 이전 배치 되돌리기를 폐기한다. 생산과 수확 기한은 서버 시각을 기준으로 하고, 저장된 수확 작업은 재진입해도 이어서 처리한다.

규칙을 바꾸면 `npm run farm:engine`으로 공통 서버 번들을 갱신한다. 앱 빌드는 번들 일치를 검사하지만 Edge Function을 자동 배포하지는 않는다. 검증된 서버 규칙을 먼저 배포한 뒤 해당 클라이언트를 배포한다. 기존에 시작한 작업의 제작법을 삭제하지 말고 수령 경로를 보존한다. DB 변경 절차는 [DB 관리](database-management.md)를 따른다.

검증은 농장 계정·Edge 테스트와 공통 계정 명령·지갑 회귀 테스트, `client-data:check`, `db:verify`, 앱 빌드를 실행한다. 원격 적용 후에는 관련 함수·권한·저장·거래 중복 방지를 다시 확인한다. 임시 검증 거래는 롤백하고 실제 플레이어의 잔액으로 검증하지 않는다. 이 검증은 과거 원격 migration 이력 전체와 로컬 이력의 동등성을 증명하지 않는다.
