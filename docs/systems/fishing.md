# 미끼·인벤토리·기본 낚시

## 어선 파견

지도에서 직접 출항과 어선 파견을 선택합니다. 조선소의 배는 영구 소유하며, 한 번에 한 척만 파견합니다. 시간은 접속 주기 선택지이고 가격은 보너스의 성격을 중심으로 정합니다. 배의 가격·시간·최소/최대 적재량·보너스는 `fishing_vessels`를 원본으로 화면에 표시합니다.

모바일 파견 준비는 보유 어선 캐러셀 → 해역 아이콘 → 미끼 적재 순서입니다. 스와이프에는 이전/다음 버튼을 함께 제공하고 배를 바꾸면 적재량을 초기화합니다. 미끼는 개별 증감·직접 입력을 지원하며 최소/가득 적재는 선택한 미끼의 보유량과 남은 적재 공간 안에서만 채웁니다. 파견 화면 전체는 뷰포트 높이에 맞춰 고정하고 미끼 선택·수량 조절은 하단에서 올라오는 모달 안에서 수행하고 모달 내용만 내부 스크롤합니다. 기본 화면에는 실은 미끼 요약과 선택 버튼만 표시합니다. 닫거나 완료해도 현재 적재 선택은 유지됩니다. 파견 버튼은 안전 영역을 확보해 하단에 유지하며 최근 기록은 표시하지 않습니다. 결과 수령 직후에는 결과 목록만 내부 스크롤하고 다시 파견 준비로 돌아갑니다. 어선 그림은 collectibles Storage의 `vessels/` 경로에서 제공하며 파견과 조선소에 같은 그림을 사용합니다. 생성 프롬프트와 업로드 경로·해시는 `assets/storage-upload/new/20261018-234954/manifest.json`에 보관합니다. 원본 PNG는 `assets/vessels/source/`에 유지합니다.

출항 시 혼합 미끼를 차감하고 배의 조건을 스냅샷으로 고정합니다. 최소 적재량은 출항 조건이며 보너스 조업은 적재량을 차지하지 않습니다. 파견은 미니게임 없이 미끼당 한 번 조업하며 `fishing_success_chance_bp`로 직접 낚시와 같은 성공 판정을 합니다. 기본 성공 40%·실패 60%이며 특수 미끼의 예외도 동일하고 보너스 조업 역시 실패할 수 있습니다. 실패한 미끼는 소모되고 개체·발견 보상은 없습니다. 성공·실패 수와 결과를 함께 저장하여 재수령으로 재추첨하지 않습니다. 수령 시 성공한 결과만 보관함과 발견 기록에 반영합니다. 등급과 주 서식지 추첨은 기본 낚시 기준을 따르되 장착 낚싯대 효과는 적용하지 않습니다. 발견선의 무료 발견 보너스는 해당 해역 미발견 후보가 없으면 진주새우로 대체합니다. 맡긴 첫인사 미끼는 전부 발견했으면 성공 판정 없이 돌려줍니다.

서버 시각·지갑 잠금·작업 식별자로 차감과 수령 중복을 방지합니다. 새로고침해도 진행 상태를 복구하며, 이미 수령한 파견의 재요청은 저장된 결과를 반환합니다. 로컬 검증은 `tests/expeditions-sql.test.ts`에서 적재량·보너스·소유권·수령·권한을 확인합니다.

귀항 알림은 서버의 `fishing-expedition-return-notices` Cron 작업이 매분 확인해 기존 우편함의 소식 알림으로 한 번만 생성합니다. 접속 중에는 기존 실시간 알림 토스트에서 파견 페이지로 이동하며, 미접속 중 완료된 알림도 재접속하면 남아 있습니다. 서버의 완료 시각보다 알림이 약 1분 늦을 수 있습니다. 기기 푸시 알림은 별도입니다. Cron 확장을 지원하지 않는 로컬 PGlite에서는 작업 자체가 실행되지 않으므로 작업 함수를 직접 호출해 검증합니다. 배포 후 `cron.job`의 해당 작업 활성 상태와 실행 이력을 별도로 확인해야 합니다.

임시 즉시 귀항은 `app_private.expedition_settings.instant_return_enabled`가 켜져 있을 때만 표시·실행됩니다. 테스트 종료 시 새 migration에서 이 값을 꺼야 하며 버튼을 숨기는 것만으로 종료하지 않습니다. 즉시 귀항은 완료 시각만 앞당기며 같은 귀항 알림을 즉시 생성합니다. 결과는 별도로 수령합니다.

## 미끼별 성공 판정

일반 미끼의 사전 성공 판정은 40%, 이슬잎 경단(bait_safe)은 100%입니다. 둘 다 미니게임 조작 실패·취소·만료 시 획득할 수 없습니다. 이미 준비한 낚시의 추첨 결과는 변경하지 않습니다. fishing_state는 기본 successChanceBp와 각 미끼의 successChanceBp를 반환합니다.

## 주 서식지와 추첨

등급은 미끼의 확률표에서 먼저 뽑으며 해역 등급으로 보정하지 않습니다. 기본 지렁이와 이슬잎 경단은 일반 77%, 희귀 20%, 특급 2.7%, 신화 0.3%입니다. 다른 미끼는 각자의 테이블 값을 사용합니다. 사전 성공 판정 40%와 미니게임은 별도입니다.

물고기·쓰레기는 같은 등급의 전체 개체가 모든 해역에서 후보가 됩니다. 장식물 미끼는 등급을 먼저 추첨하고 해당 등급의 장식물만 후보로 삼습니다. 기존 지역 전용 제한과 고철섬 사물 80% 특례는 사용하지 않습니다. 지도는 상점 전용입니다.

native_region_id / is_native는 **주 서식지**를 뜻합니다. 성공 판정 → 미끼 등급 추첨 → 주 서식지·공통·외지 그룹 추첨 → 그룹 내 개체 추첨 순서입니다. 기본 그룹 비율은 60:35:5이며, 종 수가 늘어도 그룹 전체 비율은 유지합니다. 후보가 없는 그룹은 제외하고 나머지 비율을 재정규화합니다. 해역 낚싯대는 본래 해역 그룹에 1.1배, 외지 그룹 내 해당 낚싯대 서식지 개체에 3배 보정합니다. 바다 기억 미끼는 본래 해역 그룹에 3배, 탐사선은 1.5배 보정합니다. 보정 후 그룹 비율은 재정규화되며 등급 확률은 바꾸지 않습니다. 자석·미발견 미끼는 대상 제한을 먼저 적용하고, 해당 등급 후보가 전혀 없을 때만 기존 등급 대체 규칙을 유지합니다. 장식물 미끼도 등급 결정 후 장식물 안에서 그룹을 선택하며 다른 등급으로 대체하지 않습니다.

collectible_habitats는 기존 카탈로그 및 제약 호환을 위해 유지하는 역사 메타데이터입니다. 낚시 후보 제한에 사용하지 않으며 collection_state의 habitats는 전체 해역을 반환합니다. 주 서식지는 종 필드에서 읽습니다. 새 종도 이 계약을 따릅니다.

## 최신 낚시 화면

지도는 낚시 보상에서 제외하고 지도 상점에서 구매합니다. `pick_regional_collectible`은 과거 지도 추첨 구간의 roll 값에서도 물고기·쓰레기만 반환하며, 장식물 미끼는 장식물을 반환합니다. `public.fishing_state`는 원격의 사전 낚시 payload를 유지하면서 과거 `mapChanceBp` 필드만 제외합니다. 설치와 가격은 [지도 상점](map-shop.md)을 확인합니다.

지역 낚시는 [사전 추첨 장력 미니게임](../design/fishing-minigame.md)을 사용합니다. 62 SQL 적용 후 시작 시 미끼 1개를 사용하고 성공 예정40%·등급·개체를 서버가 예약합니다. 3~5초 접근과 1초 입질 연출 뒤 길게 누르기/떼기로 버티는 힘을 조절합니다. 등급별 당김 시간·횟수와 1.5~3초 휴식은 미니게임 설계 문서를 따릅니다. 미니게임 실패·취소는 반드시 실패이고, 성공 예정과 미니게임 성공을 모두 만족해야 예약한 개체가 지급됩니다. 실패 예정은 일반 실루엣으로 진행하다 무작위 사유로 끝납니다. 성공 결과는 화면 중앙 포획 연출에서 이름·등급과 함께 확인하고 화면을 눌러 닫습니다. 실패도 전체 화면 결과로 표시하고, 게이지 상한·하한·확률상 도주에 서로 다른 퐁이 이미지를 사용합니다. 네트워크 오류는 화면 안 카드, 미끼 설명과 확률은 미끼통 모달입니다. 상단 등급 테스트는 보상 없는 로컬 연습입니다.

## 사전 추첨 낚시 (62)

[62 적용 및 API](../../supabase/sql/62-prepared-fishing/README.md). 61의 추가 실패 제거 정책을 성공 예정40%+미니게임 확정 정책으로 대체합니다. app_private.prepared_fishing_casts는 예약·미끼 소모·개체 스냅샷을 보존하며, 계정당 진행 중 예약은 하나입니다. public.prepare_fishing에서 소모/예약하고 public.finish_fishing에서 결과와 획득을 확정합니다. 단일 cast_fishing API는 차단합니다.
