# 미끼·인벤토리·기본 낚시

미끼 상점의 수량 구매는 한 번의 서버 요청에서 전체 금액 차감·전체 수량 지급·거래 기록을 함께 확정한다. 개수만큼 단일 구매를 반복하거나 잔액을 중간 단계로 표시하지 않는다. 서버는 지갑 잠금 안에서 유물 할인과 표시 단가를 검증하며, 잔액 부족·가격 변경·보유 한도 초과에는 일부 구매도 발생하지 않는다. 같은 operation_id 재요청은 기존 수량과 단가가 같을 때만 인정하고 추가 결제하지 않는다. 전송 결과를 확인하지 못한 경우 클라이언트는 기존 단가·수량으로 다시 확인한다. 이전 단일 구매 RPC는 기존 클라이언트 호환을 위해 유지한다.

## 오늘의 낚시 기록

한국 시간 자정부터 **시작한 직접 낚시**를 기준으로 조회한다. 미끼는 준비 시 소모되므로 준비 기록을 원본으로 세며, 완료 기록과 작업 ID로 합쳐 중복 계산하지 않는다. 준비 기록이 없는 과거 완료 기록도 포함한다. 실패·미완료는 시도와 미끼 사용량에 포함하지만 등급별 획득에는 완료된 성공 결과만 반영한다. 자정을 넘겨 완료해도 시작한 날에 귀속하며, 미공개 예정 보상의 등급을 통계로 노출하지 않는다. 판매·선물·유물 해제는 과거 낚시 집계를 바꾸지 않는다. 연습·통발·어선 결과는 별도 기록이므로 제외한다.

화면은 공통 계정 캐시로 읽고 낚시 완료 이벤트·재진입·자정 경계에서 갱신한다. 집계를 위해 낚시 보상·미끼 차감 로직을 변경하거나 별도 로그를 중복 적재하지 않는다. 변경 시 본인 기록 격리, 자정 경계, 실패·미완료, 준비/완료 중복 제거와 실제 사용량을 회귀 검증한다.

## 어선 파견

지도에서 직접 출항과 어선 파견을 선택합니다. 조선소의 배는 영구 소유하며, 한 번에 한 척만 파견합니다. 시간은 접속 주기 선택지이고 가격은 보너스의 성격을 중심으로 정합니다. 배의 가격·시간·최소/최대 적재량·보너스는 `fishing_vessels`를 원본으로 화면에 표시합니다.

모바일 파견 준비는 보유 어선 캐러셀 → 해역 아이콘 → 미끼 적재 순서입니다. 스와이프에는 이전/다음 버튼을 함께 제공하고 배를 바꾸면 적재량을 초기화합니다. 미끼는 개별 증감·직접 입력을 지원하며 최소/가득 적재는 선택한 미끼의 보유량과 남은 적재 공간 안에서만 채웁니다. 파견 화면 전체는 뷰포트 높이에 맞춰 고정하고 미끼 선택·수량 조절은 하단에서 올라오는 모달 안에서 수행하고 모달 내용만 내부 스크롤합니다. 기본 화면에는 실은 미끼 요약과 선택 버튼만 표시합니다. 닫거나 완료해도 현재 적재 선택은 유지됩니다. 파견 버튼은 안전 영역을 확보해 하단에 유지하며 최근 기록은 표시하지 않습니다. 결과 수령 직후에는 결과 목록만 내부 스크롤하고 다시 파견 준비로 돌아갑니다. 어선 그림은 collectibles Storage의 `vessels/` 경로에서 제공하며 파견과 조선소에 같은 그림을 사용합니다. 생성 프롬프트와 업로드 경로·해시는 `assets/storage-upload/new/20261018-234954/manifest.json`에 보관합니다. 원본 PNG는 `assets/vessels/source/`에 유지합니다.

출항 시 혼합 미끼를 차감하고 배의 조건을 스냅샷으로 고정합니다. 최소 적재량은 출항 조건이며 보너스 조업은 적재량을 차지하지 않습니다. 파견은 미니게임 없이 미끼당 한 번 조업하며 `fishing_success_chance_bp`로 직접 낚시와 같은 성공 판정을 합니다. 기본 성공 40%·실패 60%이며 특수 미끼의 예외도 동일하고 보너스 조업 역시 실패할 수 있습니다. 실패한 미끼는 소모되고 개체·발견 보상은 없습니다. 성공·실패 수와 결과를 함께 저장하여 재수령으로 재추첨하지 않습니다. 수령 시 성공한 결과만 보관함과 발견 기록에 반영합니다. 등급과 주 서식지 추첨은 기본 낚시 기준을 따르되 장착 낚싯대 효과는 적용하지 않습니다. 발견선의 무료 발견 보너스는 해당 해역 미발견 후보가 없으면 진주새우로 대체합니다. 맡긴 첫인사 미끼는 전부 발견했으면 성공 판정 없이 돌려줍니다.

서버 시각·지갑 잠금·작업 식별자로 차감과 수령 중복을 방지합니다. 새로고침해도 진행 상태를 복구하며, 이미 수령한 파견의 재요청은 저장된 결과를 반환합니다. 로컬 검증은 `tests/expeditions-sql.test.ts`에서 적재량·보너스·소유권·수령·권한을 확인합니다.

귀항 알림은 서버의 `fishing-expedition-return-notices` Cron 작업이 매분 확인해 기존 우편함의 소식 알림으로 한 번만 생성합니다. 접속 중에는 기존 실시간 알림 토스트에서 파견 페이지로 이동하며, 미접속 중 완료된 알림도 재접속하면 남아 있습니다. 서버의 완료 시각보다 알림이 약 1분 늦을 수 있습니다. 기기 푸시 알림은 별도입니다. Cron 확장을 지원하지 않는 로컬 PGlite에서는 작업 자체가 실행되지 않으므로 작업 함수를 직접 호출해 검증합니다. 배포 후 `cron.job`의 해당 작업 활성 상태와 실행 이력을 별도로 확인해야 합니다.

임시 즉시 귀항은 `app_private.expedition_settings.instant_return_enabled`가 켜져 있을 때만 표시·실행됩니다. 테스트 종료 시 새 migration에서 이 값을 꺼야 하며 버튼을 숨기는 것만으로 종료하지 않습니다. 즉시 귀항은 완료 시각만 앞당기며 같은 귀항 알림을 즉시 생성합니다. 결과는 별도로 수령합니다.

## 미끼별 성공 판정

현재 직접 낚시는 준비 단계의 별도 확률 실패 없이 보상을 예약하며, 미니게임 실패·취소·만료 시 지급하지 않습니다. 이미 준비한 낚시의 추첨 결과는 변경하지 않습니다. 통발·어선의 미끼별 조업 성공 판정과 과거 API의 성공률 필드를 현재 직접 낚시의 추가 실패 확률로 해석하지 않습니다.

## 주 서식지와 추첨

등급은 미끼의 확률표에서 먼저 뽑으며 해역 등급으로 보정하지 않습니다. 현재 확률과 특수 미끼의 시간대·순환 규칙은 카탈로그의 미끼 밸런스 프로필과 최종 `fishing_bait_balance_at`, `profile_fishing_rarity` 정의를 기준으로 확인합니다. 등급 추첨과 실제 미니게임 성공은 별도입니다.

물고기·쓰레기는 같은 등급의 전체 개체가 모든 해역에서 후보가 됩니다. 장식물 미끼는 등급을 먼저 추첨하고 해당 등급의 장식물만 후보로 삼습니다. 기존 지역 전용 제한과 고철섬 사물 80% 특례는 사용하지 않습니다. 지도는 조각 수집형과 기존 상점 판매형을 구분합니다.

native_region_id / is_native는 **주 서식지**를 뜻합니다. 일반 개체 분기에서는 등급 결정 후 주 서식지·공통·외지 그룹과 그룹 내 개체를 선택합니다. 종 수가 늘어도 그룹 전체의 가중치 계약을 유지하며, 후보가 없는 그룹은 제외하고 나머지를 재정규화합니다. 해역 낚싯대·특수 미끼의 서식지 보정은 일반 개체 선택에 적용하며 지도·유물 분류의 확률이나 등급 확률을 바꾸지 않습니다. 구체적인 가중치는 최종 개체 선택 함수와 미끼 프로필을 확인합니다. 자석·미발견 미끼는 대상 제한을 먼저 적용하고, 해당 등급 후보가 전혀 없을 때만 기존 등급 대체 규칙을 유지합니다. 장식물 미끼도 등급 결정 후 장식물 안에서 그룹을 선택하며 다른 등급으로 대체하지 않습니다.

collectible_habitats는 기존 카탈로그 및 제약 호환을 위해 유지하는 역사 메타데이터입니다. 낚시 후보 제한에 사용하지 않으며 collection_state의 habitats는 전체 해역을 반환합니다. 주 서식지는 종 필드에서 읽습니다. 새 종도 이 계약을 따릅니다.

## 최신 낚시 화면

현재 직접 낚시는 `prepare_discovery_fishing` → `prepare_discovery_cast`에서 지도 조각·유물·일반 개체를 분기합니다. 조각형 지도의 전체 그림과 수집 개수는 `fishing_map_blueprints`가 원본이며 기존 판매형 지도는 [지도 상점](map-shop.md)의 계약을 유지합니다. 일반 개체 선택기에서 지도를 제외하는 것은 별도 지도 조각 분기를 제거한다는 뜻이 아닙니다.

### 지도 조각과 유물

미끼의 확률표로 등급을 먼저 정하고 `fishing_reward_category`에서 해당 등급의 보상 분류를 정합니다. 미끼 종류와 해역은 발견 보상의 후보 해역을 제한하지 않습니다. 등급별 분기 수치는 최종 함수 정의를 확인하며, 실제 획득률에는 미끼의 등급 확률과 개인별 남은 후보가 함께 영향을 줍니다.

지도는 미해금 해역의 미획득 조각만, 유물은 활성 상태이면서 현재 보유하지 않은 동일 등급 유물만 후보가 됩니다. 분류 안에서는 남은 후보 행 중 하나를 동일하게 선택하므로 지도별 조각 수와 개인 수집 현황에 따라 해역별 비중이 달라집니다. 유물의 과거 발견 기록은 재추첨을 막지 않아 판매 후 다시 후보가 될 수 있습니다. 선택한 분류에 후보가 없으면 다른 발견 분류로 확률을 넘기지 않고 일반 개체 선택으로 돌아갑니다.

결과는 준비 시 예약하고 성공 확정 시 지급합니다. 같은 작업 재요청은 재추첨하거나 미끼를 추가 차감하지 않습니다. 지도 조각을 모두 모으면 해역을 자동 해금합니다. 이 발견 분기는 직접 낚시 전용이며 통발·어선의 일반 개체 추첨에 자동으로 추가되지 않습니다. 로컬 기대 정의와 현재 운영 적용 여부는 구분해서 확인합니다.

지역 낚시는 [사전 추첨 장력 미니게임](../design/fishing-minigame.md)을 사용합니다. 시작 시 미끼 1개를 사용하고 보상을 서버에 예약합니다. 대기·입질 확인 뒤 길게 누르기/떼기로 장력을 조절하며, 미니게임에 성공하고 예약이 만료되지 않아야 실제 보상을 지급합니다. 대기·입질 확인과 완료 제한은 [DB 관리](database-management.md)의 현재 계약을 따릅니다. 성공 결과는 화면 중앙 포획 연출에서 이름·등급과 함께 확인하고 화면을 눌러 닫습니다. 실패도 전체 화면 결과로 표시하며, 네트워크 오류는 화면 안 카드, 미끼 설명과 확률은 미끼통 모달입니다. 상단 등급 테스트는 보상 없는 로컬 연습입니다.

## 사전 추첨 낚시 (62, 과거 전환 기록)

[62 적용 및 API](../../supabase/sql/62-prepared-fishing/README.md)는 당시의 성공 예정 판정과 API 전환을 설명하는 과거 기록입니다. 현재 등급·발견·성공 계약은 위의 설명과 최종 함수 정의를 따릅니다. 예약 테이블은 미끼 소모·개체 스냅샷을 보존하며 계정당 진행 중 예약은 하나입니다. 완료 재요청은 저장한 결과를 반환하고 단일 cast_fishing API는 차단합니다.

배경음악과 효과음의 마스터 음량은 설정 화면에서 각각 조절하며 브라우저에 저장한다. 곡·효과별 기본 음량에 마스터 음량을 곱하고 재생 중인 루프·효과음에도 즉시 반영한다. 음량 변경만으로 재생을 시작하거나 기존 음소거를 해제하지 않는다. 해역 음악·음악 보관함·환경음·일회성 효과음 모두 해당 설정을 따라야 한다.
