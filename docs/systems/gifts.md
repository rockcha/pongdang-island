# 개체 선물·우편함

구현 기준: 23 SQL. [적용 SQL 및 안내](../../supabase/sql/23-collectible-gifts/README.md). 22 다음에 실행하며 이미지 재업로드는 필요 없습니다. 원격 DB 자동 실행은 하지 않았습니다.

## 사용자 흐름

1. 어항 개체 목록의 선물상자 버튼을 누릅니다.
2. 현재 친구·수량·메모를 선택합니다. 같은 종류 최대 20개, 메모 최대 300자이며 메모는 선택입니다.
3. 확인 문구를 읽고 보내면 내 어항에서 개체가 빠지고 받는 사람에게 선물 알림이 도착합니다.
4. 우편함 → 선물 → 받은 선물에서 개체와 메모를 확인하고 선물 받기를 누릅니다.
5. 26 적용 후 실제 개체가 보관함에 들어가고 도감 최초 발견에 기록됩니다. 보관함에서 원하는 어항으로 배정합니다.
6. 수령 후 이모지 하나로 한 번 답장할 수 있습니다. 발신자에게 해당 답장 알림이 도착합니다.

물고기·쓰레기·장식물을 선물할 수 있습니다. 지도·테스트 개체·판매한 개체·이미 선물 보관 중인 개체는 제외합니다. 자기 자신과 현재 친구가 아닌 사람에게는 발송할 수 없습니다. 1분당 최대 5회이며 전송 후 취소·만료는 없습니다.

## 화면과 고정 아이콘

우체통 표시 이름은 메뉴·홈·상단 알림 링크·페이지 모두 우편함입니다. 경로는 /notifications를 유지합니다.

| 탭 | 고정 아이콘 | 역할 |
| --- | --- | --- |
| 전체 | Lucide Inbox | 모든 알림 |
| 친구 | Lucide UsersRound | 친구 요청·수락 |
| 소식 | Lucide Bell | 섬 소식·시스템 알림 |
| 선물 | Lucide Gift | 선물 도착·수령·답장 |

아이콘에는 접근성 이름과 검정 배경·흰색 텍스트 툴팁을 제공합니다. 안 읽은 수를 배지로 표시합니다. 선물 탭에는 받은 선물/보낸 선물을 구분하고 30건씩 페이지로 표시합니다. 알림의 선물 보기 버튼과 실시간 토스트의 선물 보기 버튼으로 상세 내용을 열 수 있습니다.

상세 Dialog에는 개체 썸네일·이름 ×N·발신/수신자 이름·메모·날짜·수령 상태를 표시합니다. 메모는 HTML이 아닌 일반 텍스트로 표시합니다. 알림을 읽는 것과 선물을 받는 것은 별도 동작입니다. 수령하면 도착 알림을 읽음 처리합니다.

| 이모지 | 서버 키 | 발신자 알림 제목 |
| --- | --- | --- |
| 👍 | thumbs_up | 따봉을 보냈어요 |
| ❤️ | heart | 하트를 보냈어요 |
| 🥰 | thanks | 고마움을 보냈어요 |
| 😂 | laugh | 웃음을 보냈어요 |
| 🎉 | celebrate | 축하를 보냈어요 |

도착 알림 제목은 선물을 받았습니다, 수령 알림은 선물을 받았어요입니다. 선물당 한 번만 이모지 답장을 보낼 수 있고 같은 답장의 재시도는 추가 알림을 만들지 않습니다.

## 실제 데이터 모델

| 테이블/컬럼 | 역할 |
| --- | --- |
| collectible_gifts | 선물 한 통: 발신/수신자·이름 스냅샷·operation_id·개체 UUID 배열·종류 스냅샷·수량·메모·pending/claimed·반응·발송/수령/답장 시각 |
| player_collectibles.escrow_gift_id | 미수령 선물 예약. 일반 목록·어항·판매·위치 저장·재선물에서 제외 |
| notifications.gift_id | 선물 상세 연결. category=gift, kind=gift_received/gift_claimed/gift_reaction |

이전 설계안의 gift_items / gift_reactions 별도 테이블 대신, 선물 한 통에 한 종류만 담으므로 개체 ID 배열과 답장 필드를 collectible_gifts에 저장합니다. 새로운 개체는 복제하지 않습니다.

발송 시 기존 개체의 tank_id를 NULL로 만들고 user_id를 수신자로 이전하여 예약합니다. 26 적용 후 수령 시 예약을 해제하고 tank_id=NULL인 수신자 보관함에 넣습니다. (tank_id,user_id) 복합 FK를 지키며 기존 animation_seed를 유지합니다. 수신자 발견 기록은 중복 없이 추가하고 발신자의 발견·낚시 기록은 보존합니다.

발신자가 탈퇴해도 이미 이전된 미수령 개체는 보존됩니다. 수신자 탈퇴 시 해당 계정의 개체는 기존 삭제 규칙으로 제거되며 발신자에게 이름 스냅샷과 수신자 NULL 상태의 기록이 남습니다. 친구 해제 후에도 기존 선물 수령·답장은 가능합니다.

## 권한·중복 방지

- gifts SELECT는 발신자/수신자만 허용하고 직접 INSERT/UPDATE/DELETE는 차단합니다.
- 보유 개체 SELECT는 본인 소유이면서 예약되지 않은 개체만 허용합니다.
- public RPC는 INVOKER, 보호된 구현은 app_private의 DEFINER이며 auth.uid()와 소유권을 검사합니다. anon 실행은 차단합니다.
- 발신자별 advisory lock과 동일 순서의 개체 행 잠금으로 발송·판매 경합을 처리합니다.
- (sender_id,operation_id) 고유 제약으로 재시도 발송을 중복 생성하지 않습니다. 같은 ID로 친구·개체·메모를 바꾸면 거절합니다.
- 수령·답장은 선물 행 잠금으로 중복 처리하지 않습니다. 사건별 notifications 고유 인덱스로 알림도 한 번만 만듭니다.
- 예약 중인 개체에 기존 판매/배치 RPC가 접근하지 못하도록 갱신합니다. 옛 SQL을 재적용했으면 최신 23을 다시 실행합니다.

RPC: send_collectible_gift, claim_collectible_gift, react_to_collectible_gift, gift_mailbox, gift_detail. 기존 notifications Realtime 구독으로 새 선물·수령·답장을 표시하고 재접속 시 저장 상태를 조회합니다. 앱을 닫았을 때 OS 푸시는 구현 범위에 포함하지 않습니다.
