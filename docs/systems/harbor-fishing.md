# 항구 자동 낚시와 통발 설치

## 배 이미지 제작 기준

항구의 배는 화면 오른쪽으로 출항하므로, 원본 이미지와 모든 스프라이트 프레임에서 선수 또는 진행 방향을 오른쪽으로 향하게 제작한다. 조선소·항구·관리창에서도 같은 방향을 유지한다. 드론과 수거 로봇처럼 선수가 없는 기체는 전면과 작업 방향을 오른쪽으로 둔다.

이미지 생성 프롬프트에 오른쪽을 향하는 진행 방향을 명시하고, 생성 후 눈으로 확인한다. 기존 배와 같은 2×2 프레임 배치와 투명 배경을 사용하며, 프레임마다 방향·중심·크기를 일치시키고 전체 기체가 프레임 안에 들어오게 한다. 방향을 맞추기 위해 글자나 비대칭 장비가 있는 이미지를 무조건 좌우 반전하지 않는다. 생성 프롬프트와 방향 검수 결과는 해당 이미지 manifest에 기록한다.

생성 프레임의 중심 차이가 화면에서 튀는 현상을 막기 위해 현재는 첫 프레임을 고정하고 CSS로 연속적인 흔들림을 준다. 프레임 전환을 다시 활성화하려면 프레임 사이 중심과 크기가 일치하는지 먼저 검수한다.


항구는 보유한 배를 기름으로 운영하는 공간이고, 통발 설치는 꼬마 통발에 보유 미끼를 넣는 별도 기능이다. 두 기능의 비용과 보상을 섞지 않는다. 어선은 실제 미끼를 사용하지 않으며, 어선 카탈로그의 전용 어획 규칙을 출항 시 저장한다. 성공률·등급표·종류 비중·미발견 및 고유종 보정은 회수 시 이 저장본을 사용하므로 이후 미끼 변경이나 장착 낚싯대의 영향을 받지 않는다. 이전 항해에는 전환 당시의 규칙을 별도로 보존하며 원래 시간·연료·시도 횟수는 바꾸지 않는다. 어획량 범위는 출항할 때 한 번 정한 시도 횟수이며 실패가 포함된다. 항구 조업은 낚시 횟수·포획 퀘스트에 집계하지 않는다.

등급을 먼저 정하고 해당 등급 안에서 종류·서식지 그룹·개체를 추첨한다. 종류 후보가 비어 있으면 같은 등급의 남은 종류로 정규화한다. 미발견 우대는 선택된 등급·서식지 그룹 안에서 아직 발견하지 않은 개체의 가중치를 높이는 방식이며, 미발견 확정이나 최종 확률의 단순 배수를 뜻하지 않는다. 미발견 대상이 없어도 새 규칙의 항해는 정상 수확한다. 기존 미발견 확정 항해의 후보 소진 처리는 이전 규칙을 유지한다.

출항·구매·수확은 인증된 서버 RPC 안에서 처리한다. 클라이언트 타이머와 애니메이션은 표시용이며 기름 차감·귀항 가능 여부·보상 수량의 근거가 아니다. 출항 시 목적지와 배의 조건을 보관하므로 이후 상품 조정이 진행 중인 조업을 바꾸지 않는다. 수확을 완료하기 전에는 같은 배를 다시 보낼 수 없다.

두 해역 조업선은 서로 다른 해금 해역 두 곳을 선택하고 시도 횟수를 절반씩 배분한다. 두 번째 해역도 서버에서 존재·해금 여부를 확인하며 목적지와 표시 이름을 출항 스냅샷에 보관한다. 재시도 인자에는 두 번째 목적지도 포함하므로 같은 요청 ID로 목적지를 바꿀 수 없다. 기존 단일 해역 출항은 추가 인자 없이 유지한다. 서버 변경을 먼저 적용한 뒤 두 번째 해역 선택 화면을 배포한다.

배 종류와 실제 보유 배를 구분한다. 같은 종류도 구매 수에 제한 없이 각기 다른 ID로 보유·조업·수확한다. 선박 번호는 현재 보유한 같은 종류의 배와 겹치지 않게 배정하고 판매한 번호는 재사용할 수 있다. 구매 제한과 동시 출항 정원은 별개이며, 빈 선착장이 없는 새 배는 보관 목록에 둔다. 보관 목록의 배는 선착장에 배치한 뒤 출항할 수 있다. 출항한 배의 선착장 자리는 귀항 후 수확을 마칠 때까지 예약되므로 보관하거나 다른 배로 교체할 수 없다. 배 교체는 기존 배를 보관하고 새 배를 배치하는 한 트랜잭션이다. 동시 요청에서도 중복 자리 배정·구매·차감이 발생하지 않아야 한다.

부두 확장은 계정에 영구 적용하며 보유 선박 한도와 구분한다. 다음 확장 대상과 비용은 항구 상태 응답이 기준이다. 구매는 기존 항구 잠금 안에서 골드 차감·확장·거래 기록·영수증을 함께 확정한다. 요청에 목표 선착장을 포함해 다른 창의 오래된 구매가 다음 단계까지 연달아 결제하지 않게 한다. 같은 요청 재시도는 기존 영수증을 반환하며, 이미 진행 중인 항해와 예약된 자리는 변경하지 않는다. 배 배치와 자동 배정도 해당 계정이 연 선착장 범위만 사용한다.

기름 퀘스트는 기존 기간·퀘스트 ID를 그대로 사용한다. 보상 종류가 바뀌었다고 이번 기간에 이미 받은 퀘스트를 초기화하거나 추가 지급하지 않는다. 기름과 골드 보상은 서버의 수령 기록과 지갑에 함께 반영하며, 기름 한도 오류에서는 수령 기록도 남기지 않는다.

재시도는 기존 operation ID와 동일한 인자를 사용한다. 결과가 불확실한 경제 요청은 계정별 로컬 기록에 남겨 페이지를 나간 뒤에도 같은 요청을 확인한다. 보상 수령과 기록은 한 트랜잭션이며 수확 재시도로 재추첨하지 않는다. 모두 수확은 요청 시점에 귀항한 자기 배만 처리한다.

귀항 애니메이션을 끝낸 뒤 서버에 확인 상태를 기록한다. 도중에 페이지를 떠났거나 확인 통신이 실패하면 다음 방문에서 다시 귀항을 보여줄 수 있다. 이 연출은 수확 여부와 독립적이며, 모션 감소 설정에서는 이동·스프라이트 동작을 생략한다. 자동 재출항은 하지 않는다.

퇴역한 기존 배는 새 판매·파견 목록에서 제외하고 신규 출항을 서버에서도 거부한다. 이미 구매한 소유권과 출항 기록은 삭제하지 않는다. 기존 파견의 결과 수령 엔진은 비공개 함수로 보존하며 인증 사용자가 직접 호출할 수 없다. 과거 출항의 snapshot과 보너스를 유지해야 한다.

배 조건과 가격은 migration의 서버 카탈로그가 기준이다. 이미지의 생성 도구·참고 그림·프롬프트·해시는 `public/port/manifest.json`과 개별 배 manifest에 보존한다. 주요 검증은 `harbor-sql`, `harbor-fleet-migration`, `port-page`, `quests-sql`, `quests-ui`, `expeditions-sql` 테스트와 `db:verify`이며 로컬 검증과 원격 적용 확인을 구분한다.

기름 구매는 서버의 사용자별 항구 잠금 안에서 한국 시간 하루 한도를 검사한다. 재시도는 기존 영수증을 반환하고 구매량에 다시 더하지 않는다. 퀘스트로 받은 기름은 구매 한도에 포함하지 않는다. 일일 구분은 지갑 잠금을 얻은 이후의 시각으로 확정한다.

보트 밸런스는 항해 시간뿐 아니라 제한된 연료당 기대 보상을 기준으로 비교한다. 짧은 항해는 빠른 회수, 긴 항해는 접속 주기 선택에도 의미가 있다. 일반 조업선의 기대 조업량은 범위의 중간값으로 계산하고 확률상 포획 실패도 반영한다. 쓰레기 위주의 배는 재활용 재료 가치, 장식물·희귀·미발견 우대선은 수집 가치와 도감 진행도도 고려한다. 구매 가격은 반복 운항 비용과 구분하며, 현재 해역 판매가만으로 모든 해역의 수익을 보장하지 않는다. 상품 조정은 신규 출항에 적용하고 이미 출항한 항해의 규칙은 바꾸지 않는다.
