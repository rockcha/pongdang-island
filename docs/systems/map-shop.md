# 지도 상점

상점은 낚싯대·미끼·지도 탭으로 구성하며 `/shop?tab=maps`로 지도 탭을 바로 엽니다. 잠긴 해역에서도 지도 상점 링크를 제공합니다. 미끼 상점은 `fishing_state`의 실제 미끼 카탈로그를 사용하며, 구형 진주 조개 상품은 표시하지 않습니다.

지도는 `public.region_maps`에 가격과 썸네일 경로만 저장합니다. 등급은 없으며 `map_shop_state`와 항해용 `region_map`에도 지도 등급을 반환하지 않습니다. 기존 `regions.rarity` 및 과거 `collectible_species`의 map 행은 역사적 함수·아이템과의 호환을 위해 보존하지만 새 지도 상품이나 도감에서 사용하지 않습니다.

초기 가격: 산호빛 여울 500, 푸른골 해역 800, 안개달 해역 1,500, 별잠 유적 2,000, 꿈먹는 심연·태고의 원시섬 각각 3,000골드. 원본은 `supabase/catalog/catalog.json`의 `region_maps`입니다. 구매는 해역당 한 번이며 지도 실물 개체를 새로 만들지 않습니다.

해역별 시각적 의도와 보존 조건은 [해역 콘셉트](../design/region-concepts.md)를 확인합니다. 가격·순서는 카탈로그, 실제 적용 상태는 원격 조회로 확인하며 DB 변경은 [DB 관리](database-management.md)를 따릅니다.

`buy_region_map`은 인증 후 지갑을 잠그고 `operation_id`를 확인합니다. 성공한 동일 요청의 재시도에는 추가 차감하지 않습니다. 다른 상품의 같은 ID 사용, 이미 해금된 지도, 잔액 부족을 거부하며 골드 차감·해금·원장 기록은 한 트랜잭션입니다. 기존 해금과 과거 지도 아이템·선물·발견 기록은 삭제하지 않습니다.

기존 판매 지도는 낚시로 지급하지 않습니다. 신규 해역은 `fishing_map_blueprints`로 등록하면 지도 조각 수집으로 해금합니다. 직접 낚시는 미끼로 등급을 먼저 정하고, 등급별 분류 확률로 기존 포획물·지도 조각·유물을 선택합니다. 지도 조각·유물은 전용 미끼의 대상 제한과 관계없이 같은 등급의 미획득 후보만 추첨하며, 해당 분류가 비어 있으면 기존 포획물로 돌아갑니다. 다른 발견 분류의 확률을 높이거나 등급을 다시 추첨하지 않습니다. 기존 포획물에는 기존 미끼 효과·서식지 가중치를 유지하며 통발·어선에는 이 발견 추첨을 적용하지 않습니다. 확률의 원본은 해당 추첨 함수와 경계값 테스트입니다.

조각·유물은 예약에 고정하고 조작 성공 시에만 영구 발견 기록을 남깁니다. 실패·취소·만료에는 지급하지 않으며 동일 요청 재시도는 기존 결과를 반환합니다. 어항용 보관함 개체를 만들지 않으므로 배치·판매·선물·거래·생산 재료로 사용할 수 없습니다. 도감에서는 각각의 분류로 조회하며, 지도 조각은 번호별로 발견 여부를 표시합니다. 결과의 조각 번호와 수집 진행도는 다른 값입니다. 진행도는 성공 후 실제 보유 조각 수로 계산하고 결과와 함께 저장해 재시도에도 유지합니다. 모든 번호를 수집하면 기존 해역 해금 기록을 생성하며, 기존 예약·해금·획득 기록은 삭제하거나 재추첨하지 않습니다.

유물은 계정당 하나만 장착하며, 현재 보유한 유물만 선택할 수 있습니다. 장착은 무료이고 해제·교체에는 기존 유물 제거 비용만 부과합니다. 지갑 잠금 안에서 장착 상태·비용을 확인하고 거래를 기록하며 동일 요청 재시도는 중복 차감하지 않습니다. 화면의 비용과 서버의 현재 비용이 달라지면 결제 전에 거절합니다. 효과는 새 낚시·통발·생산 시작과 배 구매 시점에 적용하고 진행 중인 작업은 다시 계산하지 않습니다. 생산소 가동 수가 교체 후 한도를 넘으면 장착 변경을 거절하며 이미 가동 중인 생산소를 취소하지 않습니다. 할인한 배의 재판매는 실제 구매가를 기준으로 계산해 장착 변경으로 환급액을 늘리지 않습니다. 개인 미끼 생산의 확장 한도는 서버 상태 응답을 사용하고 기존 작업의 제작 시간은 유지합니다.

세공은 운영자만 시험할 수 있습니다. 서버의 운영자 권한을 확인하며 화면의 버튼 활성화만으로 허용하지 않습니다. 서로 다른 효과 계열의 원본 유물만 재료로 허용하고 장착한 한 개는 재료에서 제외하며, 같은 유물의 여분은 세공에 사용할 수 있습니다. 성공하면 두 재료를 소모하고 두 효과를 유지하는 개인 합성품을 만들며, 실패하면 낮은 등급 한 개만 소모합니다. 동일 등급의 실패는 무작위로 한 개를 소모합니다. 비용은 결과와 관계없이 부과하고 재시도는 같은 작업 ID의 결과를 재사용합니다. 조합별 비용·확률은 세공 migration과 경계값 테스트를 기준으로 확인합니다.

합성품은 낚시 카탈로그와 분리하여 다른 플레이어의 추첨 후보에 들어가지 않게 합니다. 첫 버전은 재세공·판매를 허용하지 않습니다. 자랑하기는 소유자의 세공 성공 기록으로 검증합니다. 기본 유물 오른쪽 아래에 결합 유물을 표시하며, 장착 시 생산소 가동 한도와 오프라인 자동 수령을 포함한 두 효과를 함께 적용합니다. 검증에는 `relic-crafting` SQL·UI 테스트와 기존 유물·수확종 회귀를 사용합니다. 테스트 지급은 별도의 중복 방지 기록을 남기고 세공 migration을 재적용하거나 보상 재시도로 수량을 늘리지 않습니다.

경제 유물도 장착된 원본 또는 합성품의 효과를 사용합니다. 미끼 반환은 직접 낚시 예약에 확률을 저장하고 성공한 포획에만 사용 미끼 1개를 돌려줍니다. 취소·실패·만료·재시도는 추가 반환을 만들지 않으며 기존 예약은 소급 변경하지 않습니다. 적금 효과는 신규 가입에 저장하여 해제·교체 이후에도 해당 약정을 유지합니다. 모든 기간에서 기본 만기 이자를 정수 골드로 계산한 뒤 그 이자의 일정 비율을 추가하고, 중도 해지와 납입 실패에는 추가 이자를 주지 않습니다. 원금에 이자율을 더하는 방식과 혼동하지 않도록 미리보기와 수령 계산을 함께 검증합니다.

유물은 별도 카탈로그로 등록하며 미등록 상태에서도 도감 분류는 표시합니다. 새 유물의 추가·퇴역은 카탈로그 원본과 migration으로 관리하고, 등록 해제나 사용을 영구 발견 기록 삭제로 해석하지 않습니다. 미발견 전용 미끼의 기존 개체가 모두 소진됐을 때는 기존처럼 사용을 거절합니다. 이 검사는 분류 추첨 전에 수행해 무료 재추첨을 막습니다.

등록할 때는 카탈로그 원본의 `fishing_map_blueprints`에 등급을 포함한 정의를 추가합니다. 잠긴 신규 해역을 먼저 등록하고 해당 해역을 `region_maps` 판매 상품에 넣지 않습니다. CLI로 빈 migration을 만든 뒤 `db:catalog -- <파일> --table regions --table fishing_map_blueprints`로 생성·검토하고 `db:context`, `db:verify`와 지도 조각·발견 보상 테스트를 실행합니다. 유물은 `fishing_relics` 범위로 생성합니다. 등록 후 조각 수·해역 ID는 변경할 수 없으며, 중단은 `enabled`로 처리합니다. 지도에는 번호별 발견 상태와 진행도가 표시됩니다. 새 해역이나 유물은 이 시스템 설치만으로 생성하지 않습니다.

새 DB는 migrations 순서대로 적용합니다. 기존 원격에는 `20261017054146_map_shop_routes.sql` 다음 `20261017054247_map_shop_catalog.sql`이 필요합니다. 별잠 유적의 실제 이미지 경로는 `map/epic/map-starruins_thumbnail.png`이며 후속 `20261017055506_correct_starruins_map_image.sql`로 정정했습니다. 이 폴더명은 과거 Storage 경로이며 지도 등급을 뜻하지 않습니다. 최초 설치용 통합본 `artifacts/map-shop-install.sql`에는 수정도 포함됩니다. 이미 설치했다면 통합본을 재실행하지 않습니다. 지도 상점 상태 문구는 '보유중'을 사용합니다. 기존 DB에 baseline이나 과거 번호 SQL을 다시 실행하지 않습니다. 원격 DDL 적용 여부는 별도 확인해야 하며 로컬 테스트는 실제 배포의 증거가 아닙니다.

검증: `tests/map-shop-sql.test.ts`, `tests/map-shop-ui.test.tsx`, `tests/collection.test.tsx`, `tests/region-map.test.tsx`. 로컬 전체 검증은 기존 legacy 39~62 동결 목록 불일치가 남아 있습니다.
