# 내 섬의 배치와 구매

섬의 보유 구조물·재료·골드는 서버가 소유한다. Query는 서버 스냅샷을, React는 아직 저장하지 않은 배치와 구매창을 관리한다. 브라우저 체험판의 코인과 보유량은 신뢰할 수 없으므로 계정 재산으로 가져오지 않는다. 이전 배치는 별도 백업 키에 남기고 계정 섬은 서버의 고정 선물로 시작한다.

구매와 판매는 기존 골드 지갑을 먼저 잠그고 섬을 잠그는 한 트랜잭션으로 처리한다. 가격·보유 한도·소유권은 서버에서 검사한다. 기본 선물 구조물은 판매할 수 없으며 시설 바로가기는 구매 대상이 아니다. 타일·땅은 전체 보유량에서 배치 수량을 뺀 보관분만 판매하며, 현재 구매가의 절반을 개당 정수 내림해 지급한다. 배치의 되돌리기·초기화는 구매 내역이나 골드를 변경하지 않는다.

실패한 쓰기를 자동 재시도하지 않는다. 응답이 끊긴 요청은 원래 operation ID와 인자를 유지하고 사용자의 결과 확인으로 재요청한다. 확정된 DB 오류만 진행 중 요청을 해제한다. 배치 저장은 revision으로 다른 기기의 수정을 보호하며, 이전 저장의 재확인 결과가 더 최신 revision을 반환하면 사용자의 초안을 유지한 채 다시 불러오기를 안내한다.

상점과 기본 선물의 원본은 공통 카탈로그다. 편집기에서 상품의 크기·지형·회전·기본 배치를 바꿀 때 서버 카탈로그와 검증 규칙도 함께 검토해야 한다. DB 변경과 카탈로그 생성·원격 적용 절차는 [DB 관리](database-management.md)를 따른다. 기존 체험판은 서버 자산에 접근하지 않는 별도 미리보기로 유지한다.

신규 섬은 헤더의 상위 분류명과 구성원을 그대로 사용해 관련 건물을 구역별로 모은다. 하위 메뉴명을 구역 이름으로 대신하지 않으며, 구역 이름은 무료 기본 구조물인 표지판에 표시한다. 기존 섬은 이전 기본 배치와 완전히 일치할 때만 새 기본 배치로 갱신하고, 직접 꾸민 섬은 위치·지형을 보존하면서 기본 구역 간판의 이전 분류명만 교정한다. 사용자가 추천 기본 배치를 적용하면 실제 보유 구조물 ID를 사용하고, 가진 타일 수량 안에서만 길과 정원을 복원한다. 배치에 쓰지 않은 구조물과 재료는 보관함에 남는다.

기본 배치를 갱신할 때 기존 플레이어의 편집 결과와 재산을 덮어쓰지 않는다. 이전 기본 상태와 일치하는 잔디만 줄이고, 다른 타일·지형·건물은 유지하며 회수된 잔디는 보유량에서 차감하지 않는다. 추가 기본 구조물은 기존 섬에 한 번만 지급하며, 지정 위치가 비어 있지 않거나 잔디를 직접 바꾼 섬에서는 보관함으로 지급한다. 땅을 판매해 기본 지형을 복원할 재료가 부족하면 기본 배치 초기화를 거절한다.

검증은 섬 SQL 테스트의 거래·권한·배치 검사와 계정 API·편집 UI·저장 초안 테스트를 함께 실행한다. 기존 골드 효과의 회귀, `client-data:check`, `db:verify`, 빌드도 확인한다. 원격 검증에서는 실제 플레이어의 잔액을 변경하지 않으며 임시 계정과 거래는 한 트랜잭션 안에서 검사하고 롤백한다.
