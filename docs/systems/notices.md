# 공지사항

광장 → 공지사항(`/square/notices`)에서 안내·업데이트·점검·이벤트 소식을 확인합니다. 유형별 필터, 제목 검색, 20건 페이지 이동, 상단 고정, 대표 이미지가 있는 목록과 별도 상세 페이지를 제공합니다. 이벤트·점검의 예정/진행/종료 표시는 설정한 기간으로 계산합니다. 기간은 한국 시간으로 입력하며 예약 게시 기능은 아닙니다.

운영자에게만 작성·관리 버튼이 표시됩니다. `/new`, `/:noticeId/edit`에서 제목(2~100자), 본문(최대 20,000자), 이미지(최대 6장), 기간, 상단 고정을 편집하고 임시 저장·게시·숨김을 선택합니다. 초안과 숨긴 공지는 일반 계정에서 조회되지 않습니다. 동시에 편집한 경우 revision 검사로 덮어쓰기를 막습니다. 응답이 끊긴 저장은 공지를 다시 열어 결과부터 확인합니다.

본문은 일반 텍스트에 `**굵게**`, `## 소제목`, `- 목록`, `[이름](https://주소)`를 지원합니다. HTML을 실행하지 않습니다. 이미지 파일 선택·드래그·붙여넣기, 대표 지정·순서 변경·본문 삽입·첨부 해제를 제공합니다. 본문에 넣지 않은 이미지는 아래에 표시합니다.

## 운영자와 적용

[공지사항 마이그레이션](../../supabase/migrations/20261016181632_notice_board.sql)을 기존 마이그레이션 다음에 적용합니다. 원격 적용이나 운영자 지정은 이 문서로 확인되지 않습니다.

운영자는 서버 관리자가 `app_private.notice_operators`에 지정합니다. 유저가 편집할 수 있는 프로필·메타데이터로 판단하지 않습니다. 대상 이메일을 확인하고 아래 SQL을 실행합니다. 이메일이 존재하지 않으면 0건이므로 결과를 확인합니다.

```sql
insert into app_private.notice_operators(user_id)
select id from auth.users where lower(email)=lower('운영자이메일')
on conflict do nothing
returning user_id;
```

권한을 제거하려면 해당 user_id 행을 삭제합니다. 작성 화면을 열어두었어도 이후 저장·업로드는 서버에서 거절됩니다. 운영자 권한 목록은 일반 클라이언트에 공개하지 않습니다.

`0@0.com` 계정용 [권한 등록 SQL](../../supabase/admin/grant-notice-operator.sql)은 계정 UUID와 이메일을 함께 확인한 뒤 등록합니다. 공지 마이그레이션 다음에 실행하며 비밀번호는 포함하지 않습니다. 파일 존재는 원격 권한 등록 완료를 뜻하지 않습니다.

## 이미지와 권한

`notice-images`는 비공개 Storage 버킷입니다. PNG·JPEG·WebP만 허용하며 장당 5MB입니다. 경로는 `공지UUID/파일UUID.확장자`이고 새 파일만 업로드합니다. 일반 계정은 게시된 공지에 실제 첨부된 이미지만 읽을 수 있습니다. 임시 저장·숨김 이미지는 운영자만 읽습니다. [Supabase Storage 접근 제어](https://supabase.com/docs/guides/storage/security/access-control)에 따라 Storage RLS를 적용했습니다.

화면은 1시간짜리 서명 URL을 사용합니다. 숨김 전 발급된 URL은 만료까지 유효할 수 있습니다. 로그인 전·익명 접근은 허용하지 않습니다. 첨부 해제는 공지 연결만 제거합니다. 저장 전 중단한 업로드를 포함해 실제 파일은 남을 수 있으며, 이후 정리 작업을 추가할 때 참조 중인 이미지를 삭제하지 않아야 합니다. 현재 Storage 삭제 정책도 참조 중인 파일을 보호합니다.

## 코드와 검증

- `src/features/notices/`: API, 목록·상세, 운영자 편집, 안전한 본문 렌더링.
- `public.notices`: RLS로 읽기 제한, 직접 쓰기 금지. `notice_save` RPC가 권한·본문·이미지·기간·수정 버전을 검증합니다.
- `notice_is_operator`: 본인의 작성 권한만 반환합니다.
- `tests/notices-sql.test.ts`: 일반 계정 쓰기 차단, 초안·숨김 비공개, 이미지 권한, 충돌·필드 검증.
- `tests/notices-ui.test.tsx`: 목록 필터, 권한 차단, 이미지 업로드·미리보기·게시 확인, HTML/위험 링크 차단.

로컬 PGlite는 Storage 메타데이터와 RLS를 검사합니다. 배포 후 실제 Storage 업로드·서명 URL 발급은 운영자/일반 계정으로 확인해야 합니다. 원격 서비스 검증은 로컬 테스트를 대체하지 않습니다.
