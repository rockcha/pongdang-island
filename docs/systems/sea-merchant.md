# 바다 상인의 의뢰

바다 상인은 보관함 개체를 소모하는 개인 일일 납품처다. 한국 날짜마다 각자의 주문을 생성하며 다른 플레이어의 납품은 내 주문을 닫지 않는다. 각 주문은 계정당 한 번 완료할 수 있고 별도의 납품 횟수 제한은 두지 않는다.

개인화 전환 당일에는 이미 발행된 공통 주문의 ID·재료·지급액을 유지한다. 본인의 기존 영수증만 완료로 인정하므로 이미 납품한 주문을 다시 지급하지 않고, 다른 사람이 완료한 주문은 납품할 수 있다. 전환일은 migration 실행 당시 한국 날짜로 저장한다. 다음 날짜부터는 플레이어별 무작위 주문을 생성한다. 과거 주문·영수증·소모 개체·골드 원장은 재작성하지 않는다. 전환일을 나중에 변경하면 기존 주문의 노출 범위가 바뀌므로 운영 중 임의로 수정하지 않는다.

주문은 첫 상세 조회에서 하나의 트랜잭션으로 생성한다. 계정과 날짜를 포함하는 advisory lock 및 고유 인덱스로 중복 생성을 막는다. 재조회·카탈로그 가격 변경·브라우저 타이머·지역·보유 개체에 따라 기존 주문을 다시 뽑거나 금액을 재계산하지 않는다. 이미 발행한 주문을 교체하려면 영수증과 이전 클라이언트의 재시도까지 별도로 검토해야 한다.

메뉴 요약은 주문을 생성하지 않는다. 아직 상세 화면을 열지 않은 날짜에도 NEW 기준 시각은 한국 자정이며, 납품 가능 수량은 실제 생성된 본인 주문과 본인 보관함으로만 계산한다. 방문 여부와 재료 준비 알림을 혼동하지 않는다.

간단한 단품 주문을 중심으로 두고 세 종류를 모으는 주문은 드문 대신 추가 보상이 크다. 수량 패턴을 먼저 정하고 주문 전체의 최고 등급을 한 번만 추첨한 뒤 물고기·쓰레기·장식물을 섞는다. 최고 등급이 희귀이면 단일 수량 슬롯 중 희귀 종류 수를 균등 추첨한다. 특급·신화는 주문당 한 종류만 포함하고 나머지는 일반으로 채운다. 종류마다 등급을 따로 뽑아 혼합 주문에서 신화 확률이 커지게 하지 않는다. 해역은 납품 조건이 아니다. 구체적인 구성과 보상은 최신 migration 및 테스트를 기준으로 한다.

납품은 전체 재료가 준비된 경우에만 완료한다. 어항에 배치한 개체, 판매한 개체, 선물·거래 예약 중인 개체는 사용할 수 없다. 납품이 도감을 해금하거나 포획 기록을 만들지는 않는다. 총 지급액은 생성 시점의 일반 판매가에 수량 패턴과 등급 구성에 따른 추가 보상을 더한다. 단품과 혼합 주문의 보상 규칙은 별도로 다룬다. 카드·확인창·영수증은 같은 총 지급액을 사용한다.

지갑 → 주문 → 개체 ID 순으로 잠근 뒤 소유권·본인 완료 여부·재료·마감·골드 한도를 검사한다. 본인 영수증이 완료 상태의 원본이며 (user_id, order_id) 고유 제약으로 중복 지급을 막는다. 판매 표시·골드 지급·납품 영수증·원장 기록은 같은 트랜잭션에서 처리한다. 전환 당일 공통 주문의 과거 완료 필드는 새 납품으로 덮어쓰지 않는다.

일시적인 통신 실패 때는 계정별로 저장한 operation ID와 문구를 재사용한다. 재시도는 날짜가 바뀌어도 기존 영수증을 반환하며 다시 재료를 소모하거나 지급하지 않는다. 같은 operation ID의 주문·문구가 다르면 충돌로 거절한다. 날짜가 지난 미완료 주문이나 다른 계정의 개인 주문은 납품할 수 없다.

원본 테이블과 생성 함수는 private이며 클라이언트의 직접 접근을 허용하지 않는다. 공개 RPC는 인증된 플레이어의 주문·보관함 수량·완료 여부만 반환한다. 영수증에는 납품 당시 공개 이름과 한마디를 보존하며 아바타는 현재 공개 프로필을 표시한다. 프로필 변경 때 이전 이미지가 삭제될 수 있으므로 당시 경로를 영구 이미지로 취급하지 않는다. 한마디는 텍스트로 렌더링한다.

검증은 tests/merchant-orders-sql.test.ts, tests/merchant-personal-transition-sql.test.ts, tests/merchant-orders-ui.test.tsx, npm run client-data:check, npm run db:verify, npm run build로 한다. 실제 구형 함수로 납품한 뒤 새 migration을 적용하여 기존 지급·소모·재시도와 다른 계정의 독립 납품을 함께 확인한다. 운영 집계는 과거와 새 영수증을 함께 포함하며 공통 주문의 옛 완료 필드를 개인 완료 수로 사용하지 않는다.
