# 만선 승부장

회차당 회사 한 곳을 선택하고, 세 해역의 최종 목표 달성률 순위로 보상받는 게임이다. 출항 1시간 전 접수하고 출항에 마감한다. 출항 후 매시간 해역 하나씩 공개하며 세 번째 공개 후 자동 정산한다.

## 바꾸면 안 되는 조건

- 미끼 후보와 예산은 [회사 설정](../../supabase/voyage-bets/companies.json)이 원본이다. 회사마다 후보 미끼 하나를 고르고 가격에 따라 해역당 횟수를 정해 소폭 변동시킨다. 서로 다른 세 해역에서 각각 그 횟수만큼 추첨한다.
- 공개 전에는 미끼·횟수·목표를 숨긴다. 접수 때 첫 해역을 공개하고, 두 번째와 세 번째 해역은 각각 조업 완료 시 공개한다. 첫 어획은 출항 후 1시간, 누적 두 해역은 2시간, 전체 결과는 3시간에 공개한다. 응답은 완료한 결과 배열의 앞부분만 구성하며 내부 모델이나 나머지 어획을 반환하지 않는다.
- 실제 해역·어획과 단계별 목표는 접수 전에 고정한다. 시간 경과는 공개 범위만 늘리며 다시 추첨하지 않는다. 목표는 공개된 첫 해역·미끼·횟수와 가능한 숨은 해역 분포로 보정한다. 실제로 뽑힌 숨은 해역이나 실적에 맞춰 목표를 정하지 않는다.
- 출항 일정 변경은 아직 출항하지 않은 예정 항차에만 적용하고 같은 회차의 어획·참가금은 보존한다. 이미 출항했거나 정산한 기록은 소급 이동하지 않는다. 같은 날 이전 시간의 저녁 회차가 있으면 새 시간의 저녁 회차를 추가 생성하지 않는다.
- 중간·최종 순위는 해당 시점의 누적 판매액을 해당 단계의 사전 목표로 나눈 비율이다. 단계별 목표를 적용하므로 초기 실적을 전체 목표와 비교하지 않는다. 정확한 정수 교차곱으로 순위·동률을 판단하며 화면의 반올림한 퍼센트로 정산하지 않는다.
- 회사 한 곳에 100골드 단위, 회차당 최대 500골드다. 회사 변경은 기존 선택의 교체이며 참가금 차액만 반영한다. 출항 후에는 수정·취소하지 못한다.
- 최종 1등은 원금 포함 3배, 2등은 1.2배, 3·4등은 지급하지 않는다. 보상 대상인 1·2위에 정확한 동률이 있으면 전원 원금을 반환한다. 3·4위만 같은 것은 반환 사유가 아니다. 최종 공개 전에는 지급액을 확정하지 않는다.
- 요청 UUID를 유지해 재시도하고, 같은 UUID의 다른 내용은 거부한다. 지갑과 회차를 잠근 뒤 서버에서 마감·금액을 검사한다. 순위 항차의 보상·동률 반환금은 기존 골드 선물 보관함에 한 번만 넣고, 수령할 때 지갑에 더한다. 보관함 생성 여부와 실제 수령 여부를 구분하며 지갑 한도에 도달해도 보상은 사라지지 않는다. 전환 전에 지갑에 지급한 항차는 보관함으로 재지급하지 않는다.
- 어획은 회사 실적 계산용이다. 플레이어 장비·발견·보관함과 무관하며 개체를 지급하지 않는다. 회사 이익과 플레이어 순손익은 구분한다.
- 알림은 기기별 명시적 동의가 있는 출항 전 알림만 예약한다. 매시간 공개 알림을 자동으로 추가하지 않는다. 회차별 한 번 예약하고 출항 시 만료시킨다.

## 모델과 밸런스 변경

카탈로그와 추첨 규칙을 읽기 전용으로 확인한 뒤 기존 모델 생성 절차를 따른다. 모델은 어종·가격·미끼 규칙 스냅샷이다. 새 카탈로그와 미래 이벤트를 자동으로 반영하지 않으며 이미 준비된 항차의 스냅샷을 덮어쓰지 않는다.

순위 보정은 `scripts/db/build-voyage-rank-calibration.mjs`에서 생성한다. 회사마다 실적 분산이 다르므로 1등 확률을 모두 25%라고 가정하지 않는다. 공개 조건별 실적 분포와 다른 회사의 경쟁 분포를 사용해 **3배·1.2배 보상을 합친 기대 지급률**을 맞춘다. 낮은 변동 회사가 2등을 자주 하고 높은 변동 회사가 1등과 하위 순위를 오가는 성격은 유지한다.

학습 표본과 별도로 실제 어획을 새로 뽑은 경쟁 검증 결과를 검토한다. 검증은 표본 추정이며 모든 공개 조합에서 정확한 동일 승률이나 지급률을 보장하지 않는다. 보상 구조상 회사들이 균등하게 선택되는 경우 평균 지급률은 약 105%이므로 운영 골드 수급도 함께 확인한다. 개별 항차의 승패를 보고 보정하지 않는다.

생성 모델·순위 보정 원본·독립 검증 자료를 보존한다. SQL 변경은 CLI로 새 migration을 만들고 최종 정의와 새 보정 스냅샷을 담는다. 최초 전환 migration의 템플릿 채우기 도구는 `scripts/db/write-voyage-rank-migration.mjs`다. 적용된 과거 migration이나 이미 사용된 보정 데이터를 다시 생성해 덮어쓰지 않는다.

## 전환과 운영

운영자는 내 섬 메뉴의 만선 승부장 바로 아래에서 **만선 승부장 테스트**에 접근한다. 서버의 운영자 허용 목록을 통과한 계정만 테스트 표본을 받을 수 있다. 생성 시 운영과 같은 추첨·보정·순위·공개 함수를 실행하고 내부 하위 트랜잭션을 항상 롤백한다. 실제 항차·어획·지갑·베팅·알림을 변경하거나 테스트 행을 남기지 않는다.

테스트 화면에서는 단계 버튼과 다음 단계로 시간을 앞뒤로 이동하고, 별도 테스트 골드로 회사 선택·취소·보상을 확인한다. 되돌리기와 반복 정산은 화면의 투영값만 바꾸므로 금액을 누적 지급하지 않는다. 새 항차 뽑기로 표본과 선택을 초기화한다. 테스트 중 포커스 복귀나 공통 주기 갱신이 표본을 다시 뽑지 않도록 이 표본 캐시만 무기한 신선 상태로 유지하며 계정 전환 시에는 공통 계정 캐시와 함께 제거한다. 실제 지갑 정산 쓰기 검증은 SQL 회귀 테스트로 별도 확인한다.

이전 초과·미달 항차는 별도 규칙 표시를 유지하고 원래 1.9배 정산 및 미지급금 처리를 보존한다. 아직 접수가 시작되지 않았고 유효 참가금이 없는 예정 항차만 순위 규칙으로 전환하며 어획은 다시 뽑지 않는다. 이전 클라이언트가 순위 항차에 초과·미달 참가금을 넣는 것은 서버에서 거부한다. 신규 클라이언트는 순위 전용 RPC를 사용한다. 실제 이전 참여가 있으면 접수·항해·정산 상태를 먼저 검토하고 UI 전환 시점을 정한다.

유지보수 Cron은 미래 항차 준비·만기 정산·보상 보관함 배송·이전 규칙의 대기 지급 재시도·기존 출항 푸시 예약을 수행한다. 시간별 결과 공개는 서버 시각에 따른 읽기 필터이므로 매시간 별도 작업이 필요하지 않다. 클라이언트는 공통 서버 캐시와 앱 시계를 사용하고 각 공개 경계에서 재조회한다. 중간 순위에는 보상 미확정을 표시하고 최종 결과에서만 순위·참가금·보상·순손익과 보관함 수령 경로를 보여준다. 운영자 테스트의 보상은 테스트 보관함 투영값으로만 보여주며 테스트 지갑에 자동 합산하거나 실제 수령 링크를 노출하지 않는다.

변경 후 SQL·UI 회귀 테스트, `npm run client-data:check`, `npm run db:context`, `npm run db:verify`, `npm run build`를 확인한다. DB 변경을 먼저 적용하고 앱을 배포한다. 원격 적용 전 프로젝트와 관련 상태를 확인하고, 적용 후 함수 정의·접근 권한·단계별 비공개·항차·Cron을 재조회한다. 전체 구조 비교나 실제 기기 푸시 전달은 별도 검증이다.
