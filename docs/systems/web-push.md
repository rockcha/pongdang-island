# 기기 푸시 알림

완료 시각은 서버에서 판단한다. 기존 notifications 생성 시 기기별 발송 대기열을 함께 기록하므로 접속 여부와 무관하게 처리한다. 기기 구독 전의 과거 알림은 재발송하지 않는다. 미끼 생산은 시작 시각을 알림 식별자로 사용해 기존 생산·수령 회계 함수를 바꾸지 않는다.

## 운영과 배포

DB는 저장소의 migration 절차로 배포한다. Edge Function `web-push`는 자체 Cron 인증키를 검사하므로 플랫폼의 `verify_jwt`는 끈다. 이 설정만 복사해 인증 검사 없이 공개 발송 엔드포인트를 만들면 안 된다.

`node scripts/setup-web-push.mjs`는 VAPID 키와 Cron 키를 Git에서 제외된 `.env.web-push.local`에 한 번 생성한다. 기존 파일이 있으면 재사용한다. 키를 출력하거나 커밋하지 않는다. 일반 배포에서 VAPID 키를 회전하면 기존 기기 구독이 깨지므로 별도의 재구독 절차가 필요하다. VAPID subject는 운영자가 연락받을 수 있는 HTTPS 주소 또는 mailto 주소로 설정하는 것이 좋다.

Migration 배포 뒤 `node scripts/setup-web-push.mjs --configure-worker`로 대상 프로젝트를 검증하고 Vault에 설정한다. 이 명령은 `.env.storage.local`의 서버 전용 키로 제한된 설정 RPC를 호출한다. 서버 비밀키와 구독 주소는 브라우저 응답·로그에 포함하지 않는다. 발송 함수는 Vault를 읽고, 선택적으로 동일 이름의 Edge 환경변수로 덮어쓸 수 있다. Vault 사용 시 CLI 로그인이나 프런트엔드 비밀키 설정은 필요 없다.

프런트엔드도 함께 배포해야 한다. 기존 Workbox 캐시·수동 업데이트 동작은 유지하고 push 수신 스크립트만 추가한다. 구버전 서비스 워커가 응답하지 않으면 설정 화면에서 앱 업데이트 후 다시 시도하도록 안내한다.

## 수신과 검증

설정 → 푸시 알림에서 기기별로 켜고 소식 종류를 선택한다. 권한 요청은 사용자가 직접 버튼을 누를 때만 호출한다. 아이폰·아이패드는 지원 OS에서 홈 화면에 추가한 웹 앱으로 열어야 한다. 알림이 차단된 기기는 브라우저/OS의 해당 사이트 알림 설정을 확인한다.

`테스트 알림 받기`를 누른 뒤 앱을 닫고 수신 여부와 클릭 이동을 실제 기기에서 확인한다. 분 단위 서버 작업과 기기·네트워크 상태 때문에 정시 도착을 보장하지 않는다. 브라우저 푸시 알림 소리는 OS 설정을 따르며 게임의 MP3 효과음과 별개다.

자동 검증은 tenant 격리·기기 구독 탈취 방지·발송 대상 호스트 제한·수령/만료 건 제외·작업 lease·재시도·잘못된 구독 제거·클릭 경로 제한·로그아웃 후 계정 불일치 차단을 다룬다. 로컬 모의 발송과 SQL 검증은 Apple/Google/Mozilla 서비스의 실제 전달 검증을 대신하지 않는다.

## 유지해야 하는 조건

- 기기 구독과 암호화 키는 private schema에 두고 클라이언트의 직접 조회를 금지한다. 발송/설정/비밀 조회 RPC는 service_role에만 허용한다.
- 완료 알림은 발송 직전에 현재 생산 실행·수령·만료 상태를 다시 확인한다. 대기열 처리의 lease 만료 재시도는 at-least-once이므로 동일 알림 tag로 표시 중복을 줄인다.
- 로그아웃 때 로컬 수신 계정부터 지우고 서버 연결·브라우저 구독을 해제한다. 서비스 워커도 계정이 맞지 않으면 표시·클릭을 거절한다.
- 푸시를 허용한 제공자 호스트만 발송한다. 새 제공자를 지원하려면 DB와 발송 함수의 허용 목록을 함께 검토한다.
- 알림 권한 철회·기기 재설치·브라우저 데이터 삭제 후에는 재구독이 필요하다. 404/410 응답의 구독은 삭제하고 일시 실패는 제한된 횟수로 재시도한다.
