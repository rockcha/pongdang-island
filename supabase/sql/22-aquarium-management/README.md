# 어항 드래그·개체 목록·판매

16/17 개체 스키마가 적용된 퐁당섬 프로젝트에서 `01-management.sql`을 SQL Editor로 실행하세요. 데이터 초기화 없이 RPC만 추가/갱신하며 반복 실행 가능합니다. 18~21 어종 등록 SQL은 독립적입니다. 원격 DB에는 자동 실행하지 않았습니다.

## 화면

- 개체를 잡아 드래그하고 놓으면 그 위치에서 유영을 이어갑니다. 물고기·쓰레기·구조물을 모두 옮길 수 있습니다.
- 실제 보유 개체의 놓은 위치는 서버에 저장합니다. 테스트 개체는 화면에서만 이동합니다.
- 좌측 상단 개체 목록 버튼은 같은 종류를 ×N으로 묶고 카테고리·등급 필터를 제공합니다.
- 우측 상단 크게 보기 버튼은 상세보기 모달을 엽니다. 상세보기에서도 드래그와 개체 목록을 사용할 수 있습니다.
- 판매는 실제 보유 개체만 가능하며 1~100개 수량과 받을 골드를 확인한 뒤 진행합니다. 테스트 개체·지도·판매가 0인 아이템은 제외합니다.

## RPC

| 함수 | 인자 | 결과 |
| --- | --- | --- |
| place_collectible | p_collectible_id, p_tank_id, p_x, p_y | id, position_x, position_y |
| sell_collectibles | p_collectible_ids(uuid[]), p_operation_id(uuid) | 최신 지갑과 delta |

좌표는 개체 컨테이너 왼쪽 위가 움직일 수 있는 범위의 0~1 비율입니다. 좌표를 저장해도 유영을 영구 고정하지 않으며 다음 화면 로딩의 시작 위치로 사용합니다. 사용자 배치 이후 높이는 어항 전체 안에서 이동할 수 있습니다.

판매는 서버 카탈로그의 sell_price로 계산합니다. 지갑과 개체를 잠그고 sold_at 기록·어항에서 제거·골드 지급·거래 이력을 한 트랜잭션으로 처리합니다. 같은 operation_id와 개체 목록의 재요청에는 골드를 추가 지급하지 않습니다. 다른 소유자, 이미 판매한 개체, 중복 ID, 잘못된 좌표, 골드 한도 초과는 거절합니다. 도감 최초 발견과 기존 낚시 기록은 유지됩니다.

공개 함수는 SECURITY INVOKER이고 실제 쓰기는 app_private의 SECURITY DEFINER에서 auth.uid()와 소유권을 검사합니다. PUBLIC/anon 실행을 막고 authenticated에만 실행 권한을 부여합니다. 클라이언트 테이블 쓰기 권한이나 RLS는 넓히지 않습니다.
