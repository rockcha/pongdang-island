# 선물·파도 우편함 적용

22번 SQL 적용 후 퐁당섬 프로젝트 SQL Editor에서 `01-gifts.sql`을 실행하세요. 반복 실행 가능하고 보유 개체·골드·낚시 기록을 초기화하지 않습니다. 별도 이미지 업로드는 없습니다. 원격 DB에는 자동 실행하지 않았습니다.

## 사용

1. 어항의 개체 목록에서 선물상자 버튼을 누릅니다.
2. 친구·수량(최대 20개)·메모(선택, 최대 300자)를 작성하고 보내기를 누릅니다.
3. 받는 사람은 파도 우편함 → 선물 → 받은 선물에서 내용과 메모를 확인합니다.
4. 선물 받기를 누르면 실제 개체가 기본 어항에 들어가고 도감에 기록됩니다.
5. 수령한 사람은 👍 ❤️ 🥰 😂 🎉 중 하나로 한 번 답장할 수 있습니다. 보낸 사람에게 해당 알림이 도착합니다.

한 번에 같은 종류만 보낼 수 있습니다. 물고기·쓰레기·구조물은 가능하고 지도·테스트 개체·판매한 개체·미수령 선물은 제외합니다. 현재 친구에게만 발송하고 자기 자신에게는 보낼 수 없습니다. 1분당 최대 5회입니다. 발송 후 취소나 자동 만료는 없습니다.

## 데이터와 권한

`collectible_gifts`에 개체 UUID 배열·수량·종류 스냅샷·메모·발신/수신자 이름·수령 상태·반응을 저장합니다. 새 개체를 만들지 않습니다. 발송 시 기존 개체는 수신자 소유의 예약 상태(escrow_gift_id)로 옮겨지고 어항에는 배치하지 않습니다. 예약 중에는 일반 보유 조회·판매·위치 저장·재선물에서 제외합니다.

이 방식으로 발신자가 탈퇴해도 수신자의 선물 개체를 보존합니다. 수신자가 탈퇴하면 해당 계정의 개체는 기존 계정 삭제 규칙에 따라 제거되며 선물 기록은 이름 스냅샷과 수신자 NULL 상태로 발신자에게 남습니다. 이미 보낸 선물은 친구 해제 후에도 수령·답장이 가능합니다.

수령 시 (tank_id,user_id) FK를 지키며 수신자의 기본 어항에 배치합니다. 도감 최초 발견은 중복 없이 추가하고 발신자의 기존 발견·낚시 기록은 유지합니다. 알림 읽음과 수령 상태는 독립적입니다.

RLS는 선물 발신자/수신자만 SELECT를 허용합니다. 직접 INSERT/UPDATE/DELETE는 허용하지 않습니다. RPC는 auth.uid()·친구·개체 소유·예약 상태를 검증합니다. 개체와 선물 행 잠금, 발신자별 advisory lock, 고유 발송 operation_id와 고유 사건 알림으로 재시도·동시 판매·동시 수령·중복 답장을 막습니다. public RPC는 INVOKER, 보호된 변경 함수는 app_private의 DEFINER이며 anon 실행을 허용하지 않습니다.

RPC: send_collectible_gift, claim_collectible_gift, react_to_collectible_gift, gift_mailbox, gift_detail. 선물함은 30건씩 페이지로 조회합니다. 기존 notifications INSERT/UPDATE 실시간 구독을 사용하며 선물 도착·수령·답장을 category=gift로 구분합니다.

23은 기존 owned_collectibles·판매·위치 저장 RPC를 갱신합니다. 22 파일에도 예약 상태를 검사하는 호환 가드를 넣어 재실행 시 예약 개체 판매가 열리지 않게 했습니다. 옛 버전 파일을 다시 적용했다면 최신 23을 재실행하세요.
