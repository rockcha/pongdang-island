# 개체 보관함과 어항 배정

기존 **25까지 적용한 DB**에서 [01-storage.sql](01-storage.sql)을 실행하고 변경된 앱을 적용합니다. 새 이미지 업로드는 없습니다. 반복 실행 가능하며 기존 개체·배치·골드·발견 기록을 보존합니다. 로컬 PostgreSQL(PGlite) 검증만 수행했으며 원격 DB에는 자동 적용하지 않았습니다.

## 사용자 흐름

- 낚시로 얻는 물고기·쓰레기·장식물은 보관함에 들어갑니다. 지도 조각은 기존처럼 항로를 해금하며 보관함 대상이 아닙니다.
- 선물은 우편함에서 **수령**하면 보관함으로 들어갑니다. 아직 수령하지 않은 예약 개체는 보관 수량에 포함하지 않고 배정할 수 없습니다.
- 아쿠아리움 좌측 상단에 개체 목록·배경·보관함 아이콘을 한 묶음으로 표시합니다. 텍스트 대신 툴팁을 사용하고, 보관함에 수량을 빨간 배지로 표시합니다. 100개 이상 배지는 99+, 툴팁·접근성 이름과 보관함 제목은 실제 전체 수량을 표시합니다.
- 보관함에서 여러 개를 선택하고 내 어항을 고른 뒤 **N개 어항에 넣기**를 누릅니다. 물고기·쓰레기·장식물을 섞어 한 번에 최대 50개 배정할 수 있습니다.
- 어항당 실제 배치 개체는 합계 50개까지 추가할 수 있습니다. 남은 칸보다 많이 고르면 배정을 막고 다른 어항을 선택할 수 있게 안내합니다. 낚시·선물 획득 자체를 막지는 않습니다.
- 개체 목록의 보관함 아이콘으로 해당 종류의 실제 보유 개체를 최대 50개씩 보관함으로 돌려보냅니다. 테스트 개체는 실제 보관함에 넣지 않습니다.
- 보관함은 검색·종류 필터·페이지당 50개 조회를 지원합니다. 선택은 필터나 페이지를 바꿔도 유지하며 선택 수량은 항상 표시합니다. 화면 선택은 현재 보이는 페이지에서 최대 50개까지 선택합니다.
- 낚시 결과에서 어항을 고르지 않습니다. 보관함으로 들어갔다는 안내만 표시합니다.

## DB 변경

별도 인벤토리 테이블을 만들지 않고 `player_collectibles.tank_id IS NULL`인 미판매·미예약 물고기/쓰레기/장식물을 보관 개체로 취급합니다. 부분 인덱스로 보관함·어항 점유 조회를 지원합니다.

- `aquarium_state`: `inhabitants`에는 배치 개체만 반환하고, `storageCount`, `tankCapacity=50`을 추가합니다.
- `collectible_storage(p_offset, p_query, p_kind)`: 본인의 보관 개체를 페이지당 50개 반환합니다. 본인·미판매·미예약·종류 조건을 서버에서 적용하며 검색은 이름의 부분 문자열로 처리합니다.
- `move_collectibles(p_collectible_ids, p_tank_id)`: NULL이면 보관함으로, 본인 어항 UUID이면 보관함에서 그 어항으로 배정합니다. 다른 어항에서 직접 가져오는 요청은 거절하므로 먼저 보관함으로 옮깁니다. 같은 어항에 이미 배정된 개체의 재시도는 위치를 초기화하지 않습니다.
- 목적지 어항 행을 먼저 잠가 동시 배정의 인원 초과를 막고, 개체를 ID 순으로 잠근 뒤 전부 검증합니다. 하나라도 다른 사용자·판매·예약·지도 등이면 전체 이동을 취소합니다. 배치 변경 시 위치만 초기화하고 장식물 회전·배율은 보존합니다.
- 낚시 상태는 미끼 목록만 반환해 전체 보유 개체를 매번 내려받지 않습니다.
- 낚시 및 선물 수령 함수는 신규 획득 개체를 `tank_id=NULL`로 저장합니다. 기존 재시도·알림·권한 검사는 유지합니다.

기존 어항이 이미 50개를 넘은 경우 강제로 빼지 않습니다. 보관함으로 옮겨 공간을 확보한 뒤 추가 배정할 수 있습니다. 클라이언트 테스트 개체는 DB 보유 개체·보관 수량·정원 계산에 포함하지 않습니다.
